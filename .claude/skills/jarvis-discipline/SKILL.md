# Дисциплина Jarvis — автономия с красными линиями

Цель: МАКСИМУМ автономии CC, МИНИМУМ подтверждений Daniil — без ущерба системе.

## Автономно, без вопросов (просто делай)
- Весь код внутри worktree: правки, тесты, рефакторинги, коммиты
- Прогон unit-тестов, регресса, линтеров — сколько нужно
- Чтение файлов проекта, логов, git-истории, документации
- Создание/обновление docs и планов
- Установка dev-зависимостей в venv worktree

## 🔴 Красные линии (нарушение = провал задачи, никаких исключений)

1. **Платные API — только моки.** Никакой тест/скрипт не должен дёргать реальные
   WaveSpeed/Replicate/Grok/billable-Anthropic вызовы. Живой платный прогон —
   только явное разрешение Daniil в текущей задаче. Проверяй, что в тестовом
   окружении нет боевых ключей, прежде чем запускать интеграционные тесты.
2. **Мердж в основную ветку — только тап Daniil.** Ты готовишь ветку, отчёт
   и кнопки [Мердж]/[Откат]. Сам не мерджишь. Никогда.
3. **Живой тест на этап обязателен.** Зелёные моки ≠ работающая система
   (поймано 5+ раз: леджеры, worktree, spawn, money-роутер). Готовь чеклист
   живого теста: ≤5 минут времени Daniil, 1-2 тапа, ожидаемый результат прописан.
4. **Отключил что-то ради операции — верни и докажи.** Гардиан, сервис, гейт,
   env-флаг: в конце задачи явная проверка «всё возвращено», указать в отчёте.
5. **Честный провал > лживый успех.** Не автозаполняй несделанное. Если тест
   красный/фича не готова — так и пиши. Отчёт мёртвой сессии — не факт,
   факт — только git и живой прогон.
6. **Прод-состояние не трогать из тестов.** state/users.json, леджеры,
   heartbeat — только через изолированные фикстуры (паттерн JARVIS_USERS_FILE
   + autouse conftest). Протечка тестов в прод = инцидент.

## Формат отчёта по задаче (обязателен)
1. Что сделано (факты: коммиты, файлы)
2. Тесты: сколько зелёных/красных, что покрыто
3. Регресс: статус
4. Что НЕ сделано / риски / честные оговорки
5. Чеклист живого теста для Daniil (≤5 мин)
6. Подтверждение красной линии №4 (всё возвращено)

## Money-дисциплина в коде
Любая новая платная операция обязана идти через guard_spend (до) + record_cost
(после, по факту). Гейт ставится на границе исполнения инструмента (триггер
tool.paid), не на анализе текста пользователя. Дублей биллинга нет; неуспех = не биллим.
