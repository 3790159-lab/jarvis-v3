### 2. Prompt-caching ⬅️ **СЕЙЧАС**
**Что.** `cache_control` на системный промпт (стабилен весь диалог) + окно истории (последние N сообщений/токенов вместо всей — закрывает и P3-стоимость, и рост ПДн P8). Плюс usage-логгер (общая точка `AnthropicLLM.complete`). Кэш **и в brain, и в классификаторе** (у обоих стабильный системный префикс).
**Критерий (Даниил):** замерить **фактическую** экономию до/после на **реальном диалоге** (`usage.cache_read_input_tokens` из ответа API), а не по прайсу-прогнозу.
**Объём.** S (окно) + M (кэш с корректной инвалидацией). Правка `core/llm.py` + `brain.py` + классификатор, аддитивная, конвейер не меняем.
**Зависимость.** Нет. Usage-логгер делаем здесь же (нужен и для замера, и для М6-расхода).
**Блокер запуска.** 🟡 До второго клиента (§11 A10) — но по указанию идёт в Спринт 0, следующим после секретов.
**Что ломается, если пропустить.** −70% расходов не получаем (см. §эконом.). Экономика при масштабе рушится: 1000 диал/мес = $350 токенов/клиент вместо $110.

### 3. P4 (Б4-хвост) + P5 (funnel-edge)
**Что.** P4 — epoch-счётчик на дебаунсере, инвалидация устаревшего ответа перед каждой отправкой. P5 — при исходящем к незнакомцу создавать контакт с флагом «инициировано нами», пускать ответы через admission.
**Объём.** M + M.
**Зависимость.** Нет. Проверяются живыми дрилами Д-7, Д-8 (TEST_MATRIX §4).
**Блокер запуска.** 🟡 **Можно после** запуска, но до заметного объёма — это то, что видит живой клиент как «глючит».
**Что ломается, если пропустить.** P4: персона договаривает поверх новой реплики лида → выглядит как глухой бот (главный провал для продукта «неотличимость от человека»). P5: диалог, начатый владельцем вручную, обрывается на первом ответе лида → потерянные лиды у риелтора/фрилансера.

## Юнит-экономика подписки

**Источник цифр:** замеры фазы 1 через `count_tokens` (AUDIT §3), не оценка на глаз. Модель — **sonnet-5**, цена по стикеру **$3 / $15** за 1M вход/выход (интро $2/$10 действует до 2026-08-31 — привожу ниже, но планировать стоит по стикеру, интро истечёт).

### ✅ ФАКТ (живой дрил volska 2026-07-23, по `llm_usage`, — заменяет прайсовый прогноз ниже)

Дрил: 8 сообщений лида (6 подряд + пауза 18.6 мин + 2), 16 вызовов (brain+классификатор), кэш включился с первого вызова (write 5163+3453 ток = посчитанный префикс), в активной фазе **100% cache-хитов**; после паузы >5 мин — повторный write (TTL), дальше снова хиты.

- **Диалог факт: $0.31** (до кэша тот же диалог стоил бы $0.44) → экономия **−28.7%**, а не прогнозные −70%.
- Почему меньше прогноза: системный промпт оказался **50% входа**, а не 87% — вторая половина это **некэшируемая история диалога** (~3.9–4.8k ток уже на старте дрила, unbounded рост) и её дубль в классификаторе. Прогноз 87% был верен для короткой истории.
- **Следующий рычаг** — окно истории + cache-breakpoint на хвосте `messages` (бэклог спеки caching): добивает остальную часть экономии.

| Диалогов/мес | До caching (факт) | После caching (факт) | Экономия |
|---|---|---|---|
| 100 | $44 | **$31** | −$13 |
| 300 | $132 | **$94** | −$38 |
| 1000 | $441 | **$314** | −$127 |

*Оговорка: дрил шёл на раздутой истории (65+ сообщений с прошлых дрилов) — это верхняя оценка; свежий лид в начале диалога дешевле. Точные цифры копятся в `llm_usage` автоматически.*

**TTL (5 мин, факт):** 2 из 14 повторных вызовов дрила промахнулись из-за паузы 18.6 мин. Исторические интервалы user-сообщений (все контакты, n=69): **64% ≤5 мин** (хит), **23% в окне 5 мин–1 ч** (промах при 5m, хит при 1h), 13% >1 ч (промах всегда). Арифметика 1h TTL (write ×2): премия первого write $0.019/диалог, выгода на каждый возврат в окне $0.030 → break-even = 0.65 возврата/диалог. Решение по 1h — за Даниилом.

### Прайсовый прогноз (истор., до замера — оставлен для сверки)

**Замеры на диалог** (средний = 10 обменов):
- Системный промпт brain: **5 168 ток** + классификатор: **3 458 ток** — оба на **каждый** ответ.
- Итого на диалог: **~99k input + ~3.6k output** → **$0.35 (стикер)** / $0.23 (интро).
- Прогноз после caching («87% входа») → ~$0.11, −70% — **опровергнут фактом выше** (реальные −28.7% без окна истории).

### Влияние few-shot примеров (М8) на стоимость

Статический блок примеров ~**1500 токенов** добавляется к системному промпту **brain** (в классификатор не идёт), на каждый из ~10 ответов диалога. Стоимость ответа (на диалог, стикер $3/$15):

| Конфигурация | $/диалог (10 обменов) | Δ |
|---|---|---|
| Без примеров, без кэша | **$0.35** | база |
| **С примерами, без кэша** | **$0.40** | +$0.045 (примеры ×10 ответов) |
| **С примерами + кэш** | **~$0.115** | +$0.005 к «после кэша» |

**Ключевой вывод:** примеры без кэша заметно дороже (+13% к диалогу), а **с кэшем — почти бесплатны** (+$0.005), потому что статичны и кэшируются целиком. То есть М8 **усиливает довод за prompt-caching** (п.2): чем больше статичных примеров, тем больше выигрыш кэша. Порядок «caching → М8» (или вместе) — не случайный: включать много примеров ДО кэша = раздувать счёт; после кэша — можно щедро, почти без цены.

Per-client/мес с примерами (стикер): 100 диал — без кэша $40 / с кэшем $11.5; 300 — $120 / $34.5; 1000 — $400 / $115. С кэшем примеры практически не сдвигают экономику; без кэша — добавляют ~15% к и без того высокому счёту.

### Что это значит для тарифа

- Ориентир подписки из проекта — **$500–1000/мес с клиента**.
- При **300 диалогов** после caching токены = **$94/мес (факт)** → валовая маржа по токенам ~81–91%. Рентабельно, но хуже прайсового прогноза ($33) — добор маржи даст окно истории (см. ФАКТ выше).
- При **1000 диалогов БЕЗ caching** = **$441/мес (факт)** → съедает большую часть тарифа $500; с кэшем $314. **Кэш + окно истории вместе делают высокообъёмных клиентов рентабельными** — окно поднимается в приоритете.
- **Осторожно с длинными диалогами:** без окна истории 30-обменный диалог ~$1 (стикер) из-за квадратичного роста истории. Окно истории (входит в п.2) это ограничивает — иначе болтливый клиент/лид раздувает счёт непредсказуемо. Это ещё один довод сделать п.2 рано.

**Вывод для Даниила:** тариф $500+ безопасен при любом реалистичном объёме **после** внедрения caching+окна (п.2). До caching — рентабельны только низко-/среднеобъёмные клиенты; высокообъёмные съедают маржу. Тарифную сетку задавать конфигом (§11 A2), пороги диалогов/мес — из этой таблицы.

**Оговорки.** Цифры — для volska-конфига (uk, sonnet-5); другой клиент с более коротким knowledge/playbook даст меньший системный промпт → дешевле. Точный per-client факт даст usage-логгер (п.4) после запуска.
