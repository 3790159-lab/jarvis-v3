# Windows Update перезагрузил прод ночью и убил долгую задачу

- **Дата:** 2026-07-15, 03:14–03:17 (подтверждено журналом System, Event 1074/6005/6006)
- **Severity:** SEV-2 (потеря незавершённой работы + незамеченный простой)
- **Обнаружено:** утром, по факту пропавшей задачи — не алертом

## Что произошло

Windows Update перезагрузил боевую машину **дважды за три минуты**. Точная
хронология из журнала System:

| Время | Событие | Что это |
|---|---|---|
| 03:14:09 | 1074 (`MoUsoCoreWorker.exe`) | «Установка пакета обновления (Запланирован…)» |
| 03:14:48 | 6006 | shutdown |
| 03:15:33 | 6005 | boot |
| 03:16:48 | 1074 (`TrustedInstaller.exe`) | «Обновление (Запланированное)» |
| 03:16:49 | 6006 | shutdown |
| 03:17:17 | 6005 | boot |

Погибла выполнявшаяся аудит-задача `dev_task` (549d1e) — долгий прогон, который к
утру должен был дать результат. Сервисы после ребута поднялись (гардианы
AtStartup), но **незавершённая работа не возобновилась**, и о её гибели никто не
узнал до утра.

🔗 **Это тот самый инцидент «backend умер в 03:14 и никто не узнал», который
породил DEV-17** (независимый мониторинг). Долгое время он числился как две
разные истории — «ребут убил задачу» и «backend молча лёг». Событие одно:
ребут был причиной, незамеченное падение backend — следствием. Единственный
механизм алертов тогда жил в heartbeat-цикле бота, то есть делил судьбу с тем,
за чем должен был следить.

## Корень

**Прод-машина находилась под управлением потребительской политики обновлений.**
ОС считала себя вправе перезагрузиться в любой момент; система про это не знала
и ничего на этот случай не предусматривала.

Второй корень: **долгие задачи не переживают рестарт по построению.** `dev_task`
привязан к процессу бота (DEV-11) — рестарт бота убивает прогон, а
boot-reconcile безусловно фейлит всё, что числилось running.

## Что сработало

- Гардианы (S4U / AtStartup) подняли сервисы после ребута без вмешательства.
  Инфраструктура выжила — погибла только незавершённая работа.

## Что не сработало

- Ни одного сигнала «машина перезагрузилась». Ребут прода — событие, о котором
  обязаны сообщать, а не выяснять утром.
- Задача умерла молча: ни «прервана», ни «возобновлена», просто исчезла.
- Окно обновлений не настроено, отложить/запретить авто-ребут никто не пробовал.
- **Ребутов было два подряд за три минуты**, и это тоже прошло незамеченным.
  Даже задача, переживи она первый ребут, погибла бы на втором — то есть простой
  «перезапустить с чекпойнта» здесь недостаточен без окна обслуживания.

## Действия

| Действие | Статус |
|---|---|
| Настроить окно обслуживания Windows Update (или запретить авто-ребут на проде) | ❌ НЕ СДЕЛАНО |
| Алерт «машина перезагрузилась» (uptime < N при старте гардиана) | ❌ НЕ СДЕЛАНО |
| Долгие задачи: чекпойнт + честный статус «прервана ребутом» вместо тихой пропажи | ❌ НЕ СДЕЛАНО (DEV-11 техдолг) |
| `JarvisOpsWatchdog` — 30с пинг /health + диск, DOWN→TG | ✅ живёт с 2026-07-15 |

⚠️ Watchdog ловит «сервис не отвечает», но **ребут, после которого всё поднялось,
для него неотличим от нормы**. Этот инцидент повторится молча.

## Урок

> **Прод-машина не имеет права перезагружаться по своему усмотрению.** Окно
> обновлений — часть конфигурации прода, а не настройка рабочего стола.

> **Всё, что длится дольше часа, обязано переживать рестарт** — чекпойнтом или
> хотя бы честной записью «прервана, причина». Задача, исчезающая молча, хуже
> упавшей: об упавшей узнаёшь.

> **«Сервисы поднялись» ≠ «инцидента не было».** Восстановление инфраструктуры
> маскирует потерю работы. Ребут прода — сам по себе событие для алерта.
