# Постмортем: фикс P18 убил классификатор на пять живых ходов

**Дата:** 2026-07-26, 01:2x · **Длительность:** ~10 минут живого времени, 5 ходов диалога · **Обнаружено:** приёмочным прогоном дрила (сам же и вскрыл)

## Что случилось

Фикс P18 («классификатор должен видеть ответ бота на своём ходу») был сделан дописыванием ответа в **массив сообщений**:

```python
window = [*window, {"role": "assistant", "text": reply}]
```

Anthropic API ответил `400 invalid_request_error: This model does not support assistant message prefill. The conversation must end with a user message.` Классификатор падал на КАЖДОМ ходу все пять шагов прогона.

## Чем это стоило

- Классификатор деградировал на всех пяти ходах → профиль не обновлялся, слот обязательств не трогался.
- **На шаге «оформлювати оплату» не ушла карточка владельцу.** Fail-safe сработал по проекту (деградация → не эскалируем, чтобы сломанный классификатор не штормил владельца), но бизнес-действие потеряно. Живого ущерба нет только потому, что лидом был сам владелец, а `funnel_gate` закрыт.
- Деньги: $0.0541 за пять ходов вместо ~$0.22 — платили только за brain. Дешевле обычного ровно потому, что половина конвейера не работала.

## Почему тесты не поймали

Тест на P18 подменял `deps.classify` фейком с сигнатурой `(history, profile=None, **kw)`. Фейк принимал ЛЮБОЕ окно и ничего не знал ни о сборке сообщений, ни о контракте API. Проверялся шов до фейка, а сломался шов после него — ровно класс DEV-19 («тест-дабл обязан совпадать с реальным»), только в другую сторону: дабл был ШИРЕ реального и потому слеп.

## Что сделано

1. Ответ текущего хода едет **системным блоком** (`_pending_reply_block`), а не репликой — и обязательно после cache-breakpoint'а, он изменчив на каждом ходу.
2. `build_classifier_messages` сам срезает хвостовые реплики бота: даже при ошибке вызывающего prefill не соберётся.
3. Сторожа: переписка обязана заканчиваться сообщением лида; ответ обязан быть в системном блоке; продовая привязка `_bind_classifier` обязана принимать то, что передаёт `run.py` (проверка по исходнику — от дрейфа сигнатуры).
4. Живой смоук ОДНИМ вызовом API до повторного прогона: `degraded=False`, `recalc` заведён на том же ходу.

## Урок

Правку промпт-конвейера нельзя принимать по офлайн-тестам с подменённым LLM-швом: контракт API проверяется только реальным вызовом. Один живой смоук стоит $0.02 и экономит человеческий прогон из пяти шагов. С этого дня — смоук перед живым дрилом, а не после.

Второй урок, помельче: дрил-харнесс отработал как надо — красное было честным и указало точно на сломанный ход. Инцидент нашёл не человек и не тесты, а прогон.
