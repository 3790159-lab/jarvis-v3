# Chatter — чеклист запуска нового клиента (за час)

**Что это.** Пошаговый прогон запуска клиента продукта `chatter/` (чат-ассистент
в личку от лица персоны). Отрепетирован на демо-клиенте без реального аккаунта
(harness гонял реальные пути `load_config → build_runner → handle_config_command
→ process_batch → admission_decision → ControlBotPoller._on_start`; 51 тест
config/admission/control green). Дата репетиции: 2026-07-19.

> **Легенда:** 📝 = РУЧНОЙ файл (команды нет — это дырка онбординга). 💬 = делается
> командой из пульта. 🔌 = внешнее действие (BotFather / my.telegram.org / логин).

---

## TL;DR — дырки онбординга (что НЕ делается командой)

Всё, что делает Аню живой на аккаунте, кроме базы знаний, требует **ручной правки
файла**. Команд для этого нет:

| Что нужно | Как сейчас | Дырка |
|---|---|---|
| Создать клиента (4 файла в `chatter/clients/<slug>/`) | 📝 руками | нет команды «новый клиент» |
| persona.md (кто такая Аня) | 📝 руками + `/reload` | нет команды правки персоны |
| playbook.md (воронка + ключевые слова эскалации) | 📝 руками + `/reload` | нет команды |
| settings.yaml (модель, язык, лимиты, allowlist, currency…) | 📝 руками + `/reload` | нет команды |
| **funnel_gate** (переворот гейта: отвечать незнакомцам) | 📝 `settings.yaml` + `/reload` | **нет команды-тумблера** |
| allowlist / denylist | 📝 `settings.yaml` + `/reload` | нет команды |
| Токен контрол-бота в `.env` | 📝 `.env` | нет команды |
| Блок `control:` (owner_chat_id / pairing_code) | 📝 `settings.yaml` | нет команды |
| API-креды аккаунта + логин сессии | 🔌 `.env` + `telethon_login` | интерактивно |
| **knowledge.md (база знаний)** | 💬 `/knowledge <текст>` | ✅ единственный контент-файл с командой |

Вывод: **`/knowledge` — единственная контент-правка через пульт.** Персона,
плейбук, настройки, гейт, списки — только файл + `/reload`. Планируя час с живым
клиентом, закладывай, что 4 файла ты готовишь заранее руками, а клиент по телефону
меняет через тебя только базу знаний.

---

## A. Разовая подготовка окружения (до первого клиента)

1. 🔌 **API-креды аккаунта.** Получить `api_id`/`api_hash` на
   https://my.telegram.org/apps → положить в корневой `.env`:
   `TELEGRAM_API_ID=...`, `TELEGRAM_API_HASH=...`.
2. 📝 **Ключ LLM.** `ANTHROPIC_API_KEY=...` в тот же `.env` (без него Аня отвечает
   на FakeLLM — только для теста).
3. 🔌 **Логин сессии аккаунта** (интерактивно, спросит телефон/код/2FA):
   `python -m chatter.telethon_login`
   Создаёт `.secrets/chatter_telethon.session` (gitignored, = полный доступ к
   аккаунту, не коммитить). Логин и рантайм по умолчанию смотрят в один session-файл.

> ⚠️ Переворот гейта (funnel_gate) безопасен ТОЛЬКО на аккаунте, ВЫДЕЛЕННОМ под
> воронку, не на личном: включённый гейт заставляет Аню отвечать незнакомцам.

---

## B. Завести клиента — 4 файла (📝, ~15 мин)

Каталог `chatter/clients/<slug>/`, все 4 файла ОБЯЗАТЕЛЬНЫ и НЕПУСТЫ (loader падает
громко на отсутствующем/пустом — проверено: пустая папка → `ConfigError`).

1. 📝 `persona.md` — кто такая Аня: тон, длина сообщений, ключевые фразы. (1-е
   непустое строка идёт в честное раскрытие «я ассистент…».)
2. 📝 `playbook.md` — воронка по стадиям + раздел `## Ключевые слова эскалации`
   (одно слово/фраза на строку — детерминированный слой, работает даже если
   классификатор лёг).
3. 📝 `settings.yaml` — обязательные ключи:
   - `model`, `language` (**только `ru`/`en`/`uk`**), `owner_id`, `persona_name`
     (**≠ owner_id**, иначе `ConfigError` — это разные люди), `work_hours`,
     `timings` (12 полей), `limits` (3 поля);
   - `telegram.allowlist` — **обязателен** для Telethon-транспорта (без блока
     `telegram` раннер не стартует);
   - бренд-safety под укр. бизнес: `currency: "грн"`, `forbidden_terms:[рубл,
     сбербанк…]`, `safe_payment_reply` (чем заменить подавленный ответ про оплату);
   - `owner_ref` (как звать владельца лиду в нужном падеже, напр. «владельцем»).
4. 📝 `knowledge.md` — **должен существовать непустым уже на первом старте**
   (заглушка `# База знаний\n(заполнить)` годится) — дальше заливается командой.

> Образец брать с `chatter/clients/demo/` — там рабочий украинский конфиг.

## C. Первый старт + база знаний (~10 мин)

5. Запустить раннер (в проде — через гардиан; вручную для проверки):
   `python -m chatter.telethon_run --personas <slug> --llm real`
   (`--personas a,b` — первый slug primary, даёт allowlist).
6. 💬 **`/knowledge <текст>`** из пульта — заливает базу знаний: пишет
   `knowledge.md` + атомарный `/reload` за один шаг. (Проверено: `✅ Базу знань
   оновлено … і перечитано`, цена оказалась на диске.)
   - `/knowledge` без аргумента — показать текущую базу.
7. 💬 **`/config`** — убедиться, что загружено (персона, язык, модель, N разделов/
   пунктов базы, статус гейта, размеры списков).
8. 💬 **`/reload`** — перечитать конфиг с диска БЕЗ рестарта после любой ручной
   правки файлов (fail-safe: кривой файл → остаёмся на старом, Аня не молкнет).
   - Опция: `control.auto_reload: true` → раннер сам перечитывает по mtime,
     `/reload` не нужен.
9. **Аня отвечает.** Написать лиду (или самому с allowlist-аккаунта) — Аня
   отвечает по новой базе. (В репетиции reply-путь `process_batch` отправил ответ.)
   - Откат правки: 💬 **`/rollback`** — вернуть предыдущий снимок конфига (снимки
     в `<slug>/.versions/`, держится 20 последних).

---

## D. Включить воронку (funnel_gate) + проверить инверсию (📝, ~5 мин)

10. 📝 В `settings.yaml` → блок `telegram`:
    ```yaml
    telegram:
      allowlist: [<id теста/VIP>]
      denylist: [<кого никогда>]     # опц.
      funnel_gate: true              # ← подтверждение «аккаунт выделен под воронку»
    ```
    затем 💬 `/reload` (или auto_reload). **Команды-тумблера нет — только файл.**
11. **Проверка инверсии гейта** (подтверждено `admission_decision`):
    | Отправитель | gate OFF | gate ON |
    |---|---|---|
    | незнакомец (не контакт) | `ignore` | **`answer`** (это лид) |
    | знакомый (`User.contact`) | `ignore` | **`notify_owner`** (Аня не отвечает, пульту капает уведомление) |
    | в allowlist (даже контакт) | `answer` | `answer` (override «всегда отвечать») |
    | в denylist | `ignore` | `block_denylist` |
    Живьём: написать с незнакомого аккаунта → Аня отвечает; написать со знакомого
    (контакт аккаунта) → Аня молчит, в пульт приходит «👤 Знакомый … написал».

---

## E. Привязать контрол-бот (пульт владельцу) (~10 мин)

Без токена пульт живёт в Saved Messages (поведение 3A) — этот шаг опционален, но
для клиента нужен отдельный бот, чтобы владелец рулил тапами со своего телефона.

12. 🔌 Создать бота в **BotFather**, взять токен.
13. 📝 В `.env`: `<CHATTER_CONTROL_BOT_TOKEN>=<токен>` (имя переменной — то, что
    стоит в `settings.yaml → control.control_bot_token_env`; сам токен в git не
    попадает).
14. 📝 В `settings.yaml` раскомментировать блок `control:` и задать ОДИН из путей
    привязки:
    - `owner_chat_id: <id владельца>` — жёсткий id-гейт (строже; id не секрет); **или**
    - `pairing_code: onboard-xxx` — одноразовый код: дать клиенту deep-link
      `t.me/<bot>?start=onboard-xxx`, тап сам шлёт `/start <код>`, код сгорает
      после привязки (charset `[A-Za-z0-9_-]`, ≤64).
15. 💬 Владелец жмёт **`/start`** (или тап по deep-link). Привязка живёт в SQLite
    (переживает рестарт), второй `/start` её не перебивает, разрыв — только
    `/unbind` от владельца. (Проверено: `/start` от чужого id → отказ; от
    владельца → привязка встала.)
16. Проверка: спровоцировать эскалацию (лид пишет «позови» / просит скидку) → в
    контрол-бот приходит карточка с кнопками (Вернуть Аню / +1ч / Открыть / Стоп /
    Оставить Ане).

---

## Быстрая верификация «всё живо»

- 💬 `/config` — персона/язык/модель верны, база знаний не 0 разделов, гейт в
  нужном состоянии.
- Тест-лид с незнакомого аккаунта → Аня ответила по базе.
- Знакомый контакт → Аня молчит + уведомление в пульт (если funnel_gate on).
- Эскалация-слово → карточка в пульт.
- Правишь файл → `/reload` → `/config` показывает новое; сломал → `/rollback`.
