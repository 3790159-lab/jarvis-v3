  Эндпоинт достижим из интернета через `api.jarvis-d.com`. Атакующий шлёт

  админ-командам** (`/dev_task`, платные команды, управление пользователями) без
  какой-либо аутентификации. Скрипт регистрации вебхука тоже не ставит secret_token.
- **Верификация аудитора:** боевой ingress форвардит весь :8010; консьюмер очереди
  в боте подтверждён; проверки секрета в коде нет. Вектор **живой**, не латентный.
- **Фикс:** сгенерировать случайный webhook-секрет, зарегистрировать через
  `setWebhook(secret_token=…)`, в приёмнике отклонять запросы с несовпадающим
  заголовком **до** записи в очередь; дополнительно ограничить ingress

## MED

### M1 · Обход allowlist shell-команд → RCE
- **file:line:** `app/services/shell_guard.py:12-40` + `app/services/executor.py:308`
- **Сценарий:** `validate_shell_command` проверяет только `shlex.split(...)[0]` против
  allowlist (в котором есть `python`, `py`, `powershell`, `pwsh`, `curl`) и блокирует
  лишь несколько литеральных подстрок. Команда затем идёт в
  `asyncio.create_subprocess_shell(command)` — реальный shell. Обходы: (а) разрешённый
  интерпретатор выполнит что угодно — `python -c "import os;os.system('…')"`;
  (б) метасимволы не блокируются — `echo x && <payload>` (argv[0]=`echo` проходит).
  Итог — произвольное выполнение кода для любого, кто может подать `SHELL_COMMAND`
  TaskDefinition в executor.
- **Фикс:** не использовать `create_subprocess_shell`; запускать распарсенный argv с
  `shell=False`; отклонять метасимволы; трактовать интерпретаторы как запрещённые для
  недоверенного ввода; валидировать весь вектор аргументов, не только argv[0].
- **confidence:** 7

- **Сценарий:** дневной лимит — не-атомарная последовательность: `check_limit`

### M8 · `subprocess` в text-режиме без `encoding=` → UnicodeDecodeError на cp1251
- **file:line:** `app/services/devtask/git_ops.py:36`; `app/services/devtask/regress_watch.py:142,212`; `app/autonomy/tools.py:314,320,334,340,348`; `app/services/safe_executor.py:55`; `app/services/supervisor.py:96,111`; `app/services/tool_executor_runtime.py:116,168`
- **Сценарий:** `subprocess.run/Popen(..., text=True)` без `encoding=` на RU-locale
  Windows декодит stdout ребёнка кодировкой cp1251. Вывод git (мердж-гейт декодит
  кириллические сообщения/имена веток), pytest с кириллическими именами тестов, любой
  emoji/UTF-8 → `UnicodeDecodeError` и падение флоу. `bootstrap_utf8.py` ставит
  `PYTHONUTF8=1` через `os.environ.setdefault` в рантайме, но для **уже
  запущенного** интерпретатора это не включает UTF-8-режим — безопасно только если
  процесс стартовал с `PYTHONUTF8=1` в окружении. Всё висит на лаунч-обёртке.
- **Фикс:** явно указывать `encoding="utf-8", errors="replace"` на каждом
  `run/Popen` с `text=True`; не полагаться на PYTHONUTF8 на старте.
- **confidence:** 6
