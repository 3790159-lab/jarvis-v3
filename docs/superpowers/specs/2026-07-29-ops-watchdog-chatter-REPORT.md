## 2. Ловушка 1 «кто сторожит сторожа» — была ОТКРЫТА, проверено фактом

Спека требовала проверить фактом. Проверил:

```
JarvisChatterGuardian : AtStartup + AtLogOn + Time(PT10M)   ← (в) сделан 25.07
JarvisOpsWatchdog     : AtStartup + AtLogOn                 ← дыры НЕТ САМОПОДЪЁМА
```

То есть мы собирались поручить chatter сторожу, который сам лежит до
перезагрузки — ровно инцидент 20–22.07, перенесённый на уровень выше.

**Сделано:** `register_ops_watchdog.ps1` получил тот же бессрочный
повторяющийся триггер `PT10M` **и проверку фактом при регистрации** — скрипт
перечитывает живой XML и падает с `throw`, если Планировщик триггер не принял.
Без этой проверки деплой 25.07 у гардиана молча оставил дыру открытой
(`[TimeSpan]::MaxValue` → `0x80041318` → таск со старым определением, а тест
был зелёным, потому что читал текст скрипта). Тот же регресс закрыт тестом.

Повтор безопасен ровно потому, что уже есть две линии защиты, обе проверены:
PID-лок в `ops_watchdog_detached.ps1` («another ops watchdog already running»)
и `MultipleInstances IgnoreNew` у таска.

> 🔎 **Попутная находка, вне объёма:** у `JarvisBotGuardian` тоже НЕТ временного
> триггера (только `AtStartup`+`AtLogOn`) — та же дыра 1, что чинили у chatter.
> `JarvisBackendGuardian` прикрыт (`PT5M`). Не трогал: за рамками этой спеки.

## 5. Шаги деплоя (за тобой)

Порядок важен: сначала самоподъём сторожа, потом пробы — иначе на время между
шагами chatter поручен сторожу без самоподъёма.

1. **Мерж** `arc/ops-watchdog-chatter` → `phase-4.0-unified-jarvis` (ff), скан, пуш.
2. **Перерегистрировать таск** (это и есть ловушка 1):
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File C:\jarvis\scripts\register_ops_watchdog.ps1
   ```
   Скрипт сам перечитает XML и упадёт, если триггер не принят. Ждём в выводе
   `Repetition: PT10M, duration '' (пусто = бессрочно)`.
3. **Проверить фактом:**
   ```powershell
   (Get-ScheduledTask -TaskName 'JarvisOpsWatchdog').Triggers |
     ForEach-Object { $_.CimClass.CimClassName + ' ' + $_.Repetition.Interval }
   ```
   Ждём три строки, третья — `MSFT_TaskTimeTrigger PT10M`.
4. **Перезапустить таск**, чтобы watchdog поднялся на новом коде:
   ```powershell
   Stop-ScheduledTask -TaskName JarvisOpsWatchdog
   Start-ScheduledTask -TaskName JarvisOpsWatchdog
   ```
   ⚠️ Раннер и гардиан chatter при этом НЕ трогаем — это разные таски.
5. Один цикл (30 с) → в `state/ops_watchdog_state.json` появятся ключи
   `chatter_runner` и `chatter_guardian` со счётчиком `fail: 0`.

Откат: `git revert` мержа + перерегистрация таска старым скриптом. Пробы
исчезнут, `evaluate()` заморозит их состояние — ложных ✅ не будет.

## 6. План живой приёмки — kill-дрилы

Все дрилы **бесплатные по API** (0 вызовов LLM): сторож не разговаривает с
моделью, а раннер за время дрила не обрабатывает лидов, если писать в него не
будем. Стоимость — только простой chatter, указан ниже.

**Готовность до старта:** распечатать список «НЕ трогаем» глазами (backend, бот,
их гардианы) и убедиться, что `funnel_gate: false` — дрилы не должны совпасть с
живым лидом.

### Дрил 1 — раннер умер, гардиан жив (проверка дублирования, §6.1 спеки)

- **Убиваем:** launcher-PID раннера по точному матчу `chatter.telethon_run`
  (`taskkill /PID <pid> /T /F`). **Не** по `*guardian*` — этот паттерн 24.07
  снёс главный бот.
- **Обязано случиться:** ①  в течение ~2 мин алерт от **ops_watchdog**
  («CHATTER раннер (независимый сторож)»); ② алерт от `chatter_watch_check`
  (старый канал, текст другой); ③ гардиан сам поднимает раннер за ~90 с
  (debounce 3×30 с); ④ парные ✅ от обоих каналов.
- **Провал, если:** пришёл только один алерт (значит каналы не независимы) или
  тексты неразличимы (ловушка 2).
- **Цена:** простой chatter ~1.5–2 мин. $0.

### Дрил 2 — гардиан умер, раннер жив (ГЛАВНЫЙ, закрывает дыру 2)

- **Убиваем:** PowerShell-процесс гардиана по PID из
  `state/locks/chatter_guardian.pid` (сейчас 5964). Раннер НЕ трогаем.
- **Обязано случиться:** алерт **только** от `ops_watchdog`
  («CHATTER гардиан (независимый сторож)»). Сегодня в этом сценарии не приходит
  **ничего** — это и есть закрываемая дыра.
- **Восстановление:** таск поднимет гардиана сам в пределах 10 мин (новый
  триггер). Это заодно **живая проверка ловушки 1**.
- **Провал, если:** тишина (дыра не закрыта) или гардиан не поднялся за 10 мин
  (триггер не принят Планировщиком — см. шаг 3 деплоя).
- **Цена:** до 10 мин без гардиана при живом раннере (лиды обслуживаются). $0.

### Дрил 3 — умерли оба (§6.3)

- **Убиваем:** гардиана, затем раннера.
- **Обязано случиться:** алерты по обеим пробам; после самоподъёма таска обе
  возвращаются в ✅ **без ручного вмешательства**.
- **Цена:** простой chatter до ~10 мин. $0.

### Дрил 4 — semidemo-флаг лежит, всё живо (ловушка 4)

- **Ничего не убиваем.** Просто ждём 2–3 цикла.
- **Обязано случиться:** **ни одного** алерта.
- **Провал, если:** сторож кричит на законное состояние.
- **Цена:** 0.

### Дрил 5 — сам сторож (ловушка 1, живьём)

- **Убиваем:** процесс `ops_watchdog_detached.ps1` (PID из
  `state/locks/ops_watchdog.pid`).
- **Обязано случиться:** таск поднимает его сам в пределах 10 мин; heartbeat
  `state/ops_watchdog_heartbeat.txt` снова тикает.
- **Провал, если:** не поднялся — значит мы охраняем chatter сторожем, которого
  никто не охраняет.
- **Цена:** до 10 мин без независимого сторожа. $0.

**Суммарно:** ~25 минут, $0 по API, максимальный простой chatter — около 10 минут
в дриле 3. Рекомендую прогон в окно, когда лидов заведомо нет.
