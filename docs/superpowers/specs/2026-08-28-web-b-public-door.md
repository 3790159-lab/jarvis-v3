# ВЕБ, волна 1 / пара B: публичная дверь — первая точка входа в систему

**Дата:** 28.08.2026 · **Статус:** 🟢 **КОД ПИШЕМ СРАЗУ** (владелец снял ожидание ОК 28.08)
**Основание:** замер мультиканальности §3 («плюс общее с переездом: публичная
дверь, её нет вовсе») и предспека переезда §11.
**Сверено по дереву:** `fa2554a8`
**Связано:** [[jarvis-cloud-split-prespec]], [[jarvis-panel-cookie-per-browser]],
[[jarvis-retry-loops-without-backoff]]

## §0 Что решает спека

**Решает:** как в систему попадает HTTP-запрос СНАРУЖИ, кто его пускает, и что
происходит, когда дверь настроена наполовину.

**НЕ решает:** что делать с принятым сообщением. Дверь отдаёт его в приёмник
(`sink`) и про очередь, схему и мозг не знает ничего. Приёмник — волна 2.

**НЕ решает** и вебхук Meta: у той двери чужая аутентификация (подпись
`X-Hub-Signature-256`) и чужой график ревью. Здесь оба конца НАШИ — виджет и
сервер, — и это единственная причина, по которой веб можно сделать раньше и
без чужого ревью (§5 замера).

---

## §1 Замер: двери нет ни одной

Живой `~/.cloudflared/config.yml`:

```
ingress:
  - hostname: ssh.jarvis-d.com -> ssh://localhost:22
  - hostname: rdp.jarvis-d.com -> rdp://localhost:3389
  - service: http_status:404
```

Входящей HTTP-двери нет. Панель слушает тайнет и `0.0.0.0` отвергает громко.
Бот живёт поллингом. **Система дожила до сегодня без единой публичной точки
входа** — не по недосмотру, а потому что единственный канал это позволял.

## §2 Решения

### §2.1 Дверь ВЫКЛЮЧЕНА по умолчанию и включается секретом

Роут не монтируется вовсе, пока не задан `JARVIS_PUBLIC_DOOR_KEY`. Нет ключа —
приложение поднимается как сегодня, двери не существует.

**Решил так, потому что** это ровно тот образец, которым уже живут панели
(`JARVIS_PANELS_KEY`, «вимкнено за замовчуванням»), и потому что мерж этой
арки не должен ничего открывать наружу сам по себе. Открывает — владелец,
отдельным действием, когда захочет.

### §2.2 Полу-настроенная дверь — ОТКАЗ, а не «как-нибудь»

Ключ есть, а список клиентов пуст; клиент объявлен без токена; токен короче
32 символов — **дверь не поднимается и говорит, чего не хватает**. Молча
принять запрос в такой конфигурации нельзя.

### §2.3 Каждый запрос предъявляет токен КЛИЕНТА, а не общий

Токен на клиента, сверяется `hmac.compare_digest` (не `==`: сравнение строк
утекает по времени). Общий ключ двери открывает только сам факт монтирования
роута; кто пишет — решает клиентский токен.

**Решил так, потому что** один общий токен на всех означает, что утечка у
одного клиента открывает диалоги остальных.

### §2.4 Ответ НЕ рассказывает, что не сошлось

Неверный токен, неизвестный клиент, выключенный клиент — один и тот же `401` с
одним телом. Разные ответы превращают дверь в оракул для перебора.

### §2.5 Лимит на клиента И на адрес, с бэкоффом

Потолок запросов в минуту на клиента и на IP. Превышение — `429` с
`Retry-After`.

**Решил так, потому что** без лимита первый же цикл без бэкоффа на той стороне
съест процесс: ровно этим 27.08 набралось 43418 трейсбеков за сутки
([[jarvis-retry-loops-without-backoff]]). Дверь обязана уметь сказать «позже», а
не только «нет».

### §2.6 Тело ограничено по размеру ДО разбора

Потолок байт проверяется раньше, чем JSON попадёт в парсер. Разбор
неограниченного тела — способ уронить процесс одним запросом.

### §2.7 Приёмник — ШОВ, а не вызов

Дверь зовёт `sink(envelope) -> None`, переданный при сборке. В волне 1
умолчание — приёмник, который НИЧЕГО не хранит и возвращает `202`. Волна 2
подставит очередь.

**Решил так, потому что** дверь и хранилище — разные предметы с разной
приёмкой, а `chatter/storage/db.py` сейчас занят аркой DEV-48. Шов позволяет
делать их параллельно и не драться за файл.

### §2.8 След на диске остаётся ВСЕГДА

Каждый отказ (401/429/413) и каждый приём — строка в
`state/public_door.jsonl`: время, клиент (или `?`), исход, причина. Без тела
запроса и без токена.

**Решил так, потому что** дверь наружу без следа — это ровно та тишина, из-за
которой 26.08 сутки никто не знал об обрыве.

### §2.9 Проба в `ops_watchdog`

Лампа `public_door`: выключена — `off` (не красное, это нормальное состояние);
включена и не отвечает — красное; включена и **принимает запрос без токена** —
красное громко.

**Решил так, потому что** проба «дверь жива» без проверки «дверь отказывает
чужому» — это лампа, зелёная у распахнутой двери.

## §3 Что откладываем НАМЕРЕННО

* **подпись Meta** (`X-Hub-Signature-256`) — она нужна Instagram/WhatsApp, у
  нашего виджета её нет и не будет;
* **склейка посетителя** (один человек с двух устройств) — решение владельца;
* **приём файлов** — вместе со всей медиа-веткой;
* **сам конфиг `cloudflared`** — правка живого ingress это действие владельца.
  Спека даёт готовый фрагмент и пробу, но конфиг не трогает.

---

## §4 Риск, названный прямо

**Это первая по-настоящему публичная точка входа.** Ошибка здесь стоит не
«чужой увидел панель», а «чужой ПИШЕТ в диалоги клиента». Поэтому: выключено
по умолчанию (§2.1), fail-closed на полу-настройке (§2.2), единый ответ на все
отказы (§2.4), лимит (§2.5), потолок тела (§2.6) и след (§2.8) — каждое из
шести со своим сторожем.

---

## §5 Сторожа — от спеки, до кода. Пишет ДРУГОЙ автор

1. Ключа двери нет → роут НЕ смонтирован (не 404 у смонтированного, а
   отсутствие маршрута).
2. Ключ есть, клиентов нет → сборка ОТКАЗЫВАЕТ и называет причину.
3. Клиент без токена / токен короче 32 → отказ сборки, причина названа.
4. Верный токен → `202`, `sink` позван РОВНО один раз, конверт целый.
5. Неверный токен, неизвестный клиент, выключенный клиент → **три
   одинаковых** `401`: тело и заголовки совпадают побайтово.
6. Сравнение токена — `hmac.compare_digest` (пин по AST: `==` на токене
   краснеет).
7. Превышен лимит на клиента → `429` с `Retry-After`.
8. Превышен лимит на IP при РАЗНЫХ клиентах → тоже `429` (иначе лимит
   обходится сменой клиента).
9. Тело больше потолка → `413`, и парсер JSON **не звался** (пин: подсунуть
   тело, на котором парсер упал бы).
10. `sink` бросил → дверь отвечает `503`, а НЕ `202`; приём в след не пишется
    как успешный.
11. Каждый из исходов 202/401/429/413/503 оставил строку в
    `state/public_door.jsonl`; токена и тела в ней НЕТ (пин на утечку).
12. Проба `ops_watchdog`: выключенная дверь = `off`; отвечающая = зелёная;
    **принимающая без токена = красная**.

---

## §6 Приёмка

* сторожа §5 красные до кода, зелёные после;
* мутационный гейт: мишень на каждое решение §2.1–§2.9;
* полная суита, дифф поимённо двухступенчато;
* мерж — по кнопке. **Включение двери наружу — отдельное действие владельца
  ПОСЛЕ мержа**, и оно в приёмку арки не входит.
