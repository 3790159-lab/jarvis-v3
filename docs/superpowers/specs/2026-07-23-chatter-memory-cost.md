# Спека: память лида + модель стоимости (арка «память + стоимость»)

**Статус:** черновик на согласование Даниила. Кода нет и не будет до ОК.
**Константы** — из фактического замера 2026-07-23 (`llm_usage`, volska/sonnet-5,
стикер $3/$15 за 1M): система brain 5163 ток (с М8-примерами ≈ 6.5k) +
классификатор 3453 ток — кэшируются (1h TTL, write ×2, read ×0.1); история
диалога растёт ~**140 ток/обмен** и едет НЕкэшированной в ОБА вызова; выход
~232 ток/обмен (brain 140 + классификатор 92).

## A. Модель стоимости от длины диалога

Каждый обмен тащит всю историю в два вызова → квадратичный рост:
`uncached(N) ≈ 120·N + 140·N·(N−1)` токенов за диалог из N сообщений лида.

**$/диалог (одна сессия, кэш живёт):**

| Сообщений лида | Uncached input | Стоимость диалога | $/сообщение |
|---|---|---|---|
| 5  | 3.4k  | **$0.09** | $0.018 |
| 15 | 31k   | **$0.23** | $0.016 |
| 30 | 125k  | **$0.61** | $0.020 |
| 60 | 503k  | **$1.92** | $0.032 |

(Состав: uncached ×$3/M + write 8.6k×$6/M на сессию + read 8.6k×$0.3/M на
обмен + выход ×$15/M. Дрил N=8 дал $0.31 при уже раздутой истории — модель
согласуется с фактом.)

**Возвращающийся клиент, 4 сессии/мес × 15 сообщений (история копится, окна нет):**

| Сессия | История на старте | Uncached за сессию | Стоимость |
|---|---|---|---|
| 1 | 0     | 31k  | $0.19 |
| 2 | 2.1k ток | 94k  | $0.38 |
| 3 | 4.2k ток | 157k | $0.57 |
| 4 | 6.3k ток | 220k | $0.76 |
| **Итого/мес** | | 503k | **≈ $2.07** |

Каждая следующая сессия дороже предыдущей — плата за «помнит всё дословно».
Та же нагрузка с профилем+окном (см. B): **≈ $1.18/мес (−43%)**, и разрыв
растёт с длиной. Эти две таблицы идут в юнит-экономику ROADMAP после ОК.

## B. Профиль лида (решает память И деньги)

**В промпт вместо сырой истории едут:**
1. **Последние N сообщений дословно.** Предлагаю **N = 24** (12 обменов):
   по замеру это ~1.7k ток некэшированной истории — плато вместо квадрата.
   Больше N — дороже, меньше — Ольга теряет нить внутри сессии. Per-client
   параметр в settings.yaml (`limits.history_window`), дефолт 24.
2. **Компактный профиль контакта** (~300–500 ток, структурированный текст):
   хто/сфера/проєкт, названные вилки (услуга → вилка → когда), договорённости,
   возражения, статус воронки, ключевые даты, «передумав: X → Y». Хранится в
   БД (таблица `contact_profile`: contact_id, text, updated_at, version),
   переживает недели.
3. **Старое — в архив:** сырые сообщения остаются в `messages` (ничего не
   удаляем), просто не едут в промпт.

**Обновление профиля — расширением классификатора (рекомендация).**
Классификатор УЖЕ читает всю переписку каждый ход. Расширяем его JSON-контракт
полем `profile_patch` (что нового узнали / что изменилось; пусто = нет правок).
- Стоимость: +~50 ток выхода/ход ≈ **+$0.045 на 60-сообщенийного клиента/мес**
  — на порядок дешевле отдельного вызова (~$0.5/мес) и без новой точки отказа.
- Fail-safe как у классификатора сейчас: деградация → профиль просто не
  обновился этим ходом, следующий ход догонит (история в окне ещё жива).
- Риск потери контекста: событие старше окна И не попавшее в профиль теряется.
  Смягчение: patch применяется КАЖДЫЙ ход (пока факт ещё в окне — минимум 12
  обменов на попадание в профиль), а не при паузах.

**Конфликт фактов:** last-write-wins + явная строка «передумав: раніше X,
тепер Y» в профиле (модель видит эволюцию, не противоречие). Профиль
версионируется (version++), старые версии в БД для отладки.

**Кэш (ключевое взаимодействие с 1h TTL):** профиль — часть **кэшируемого
префикса** (system), но в промпт подаётся **снапшот на начало сессии**:
- внутри сессии префикс стабилен → кэш живёт;
- обновлённый профиль подхватывается при возврате после паузы **> 1h — ровно
  когда кэш и так истёк по TTL**. Инвалидация бесплатна. Пауза 5мин–1ч:
  кэш жив, профиль в промпте чуть отстаёт, но свежие факты — в окне дословно.
- Свежайшие patch'и текущей сессии в промпт не нужны: их несёт само окно.

**Приёмочный тест (требование Даниила):** диалог → пауза (симулированная,
clock-инъекция) → возврат: (офлайн) промпт содержит профиль с проектом и
договорённостями, окно — только последние N; FakeLLM-сценарий «бот ссылается
на проект, не переспрашивает сферу». Живой дрил: диалог сегодня → возврат
завтра → Ольга помнит проект/вилку/договорённость без повторных вопросов.

## C. Простой профиль vs граф знаний (Graphiti/Zep)

| | Профиль в нашей БД | Graphiti (self-host) / Zep (managed) |
|---|---|---|
| Инфра | 0 нового (SQLite есть) | Neo4j/FalkorDB + сервис / внешний SaaS |
| Стоимость LLM | +$0.045/клиент/мес (патч классификатором) | экстракция сущностей ~сопоставимо или дороже (отдельные вызовы на episode) |
| Сложность | ~2-3 дня TDD, детерминированные тесты | интеграция+операционка+обновления; тесты против графа |
| Что даёт сверх | — | темпоральный граф, cross-session запросы «что менялось», связи между лидами |
| ПДн | данные лидов остаются на машине | **Zep = ПДн лидов в чужом облаке** (для укр. клиентов — стоп-фактор); Graphiti self-host ок, но +attack surface сразу после RCE-lockdown |
| Масштаб окупаемости | 1–10 клиентов, десятки лидов | сотни лидов/клиентов, аналитика по базе, дашборд v2 |

**Рекомендация:** простой профиль сейчас. Наш масштаб (один аккаунт, десятки
лидов) не задействует ни одну сильную сторону графа, а цена — инфра, ПДн-риск
и недетерминированные тесты. Graphiti пересмотреть при мультиклиентском
дашборде v2 (там появятся cross-session запросы, ради которых граф существует).
Решение — Даниила.

## Условие 4 Даниила (перед мержем, 2026-07-23): потолок профиля

Профиль в uncached_suffix (отклонение одобрено) → НЕ кэшируется и платится
полностью на каждом вызове (brain + classifier). Его рост = прямой рост
стоимости — тот же D1 этажом выше. Закрыто:
- **Жёсткий бюджет:** `settings.limits.profile_budget_tokens` (per-client,
  дефолт 250 ток ≈ 750 симв). Сверх бюджета профиль НЕ применяется (старый
  жив) + событие `classifier_error` с классом «бюджет» + log.warning —
  ЯВНАЯ деградация, не тихая обрезка.
- **Просьба < потолка:** промпт классификатора просит ⅔ бюджета
  (250 ток → «до 500 символов») — модель не считает символы точно, запас
  держит нормальную работу вне зоны отсечения.
- **Правило вытеснения (в промпте):** первыми выбрасываются устаревшие
  пометки «(раніше X — передумав)» и закрытые вопросы; НИКОГДА — клиент и
  проект, названные вилки цен, договорённости, статус воронки.
- **Компакция:** «профиль переписывается КОМПАКТНО: ужимай, а не накапливай».
- **Тесты:** 6 шт. в test_lead_memory.py (поле лимита, промпт-контракт,
  прод-шов `_bind_classifier` на НЕдефолтном бюджете, оверсайз → явная
  деградация + старый профиль жив, длинная история → компактный профиль в
  бюджете применяется с ключевыми фактами).
