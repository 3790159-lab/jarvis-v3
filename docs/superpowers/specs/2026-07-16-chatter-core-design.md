# CHATTER-1 — Ядро чатера (арка 1 из 3)

**Дата:** 2026-07-16
**Статус:** принят к реализации
**Продукт:** настраиваемый чат-ассистент, ведёт переписку в личке от лица персоны клиента (предприниматели; реклама из инсты → TG-личка). Продаётся за $500–1000/мес.
**Эта арка:** ядро без транспорта Telegram (фейковый транспорт). Арка 2 — Telethon-юзербот. Арка 3 — эскалация.

---

## 1. Архитектурное требование (критично)

Новый автономный пакет `chatter/` в корне репозитория `C:\jarvis`.

- **НУЛЕВАЯ связность с `app/` и `tools/`.** Ни одного `import app` / `from app` / `import tools` внутри `chatter/`. Обеспечивается тестом-стражем (грепает дерево `chatter/`, падает при любом таком импорте).
- Свои зависимости: `chatter/requirements.txt` (`anthropic`, `PyYAML`).
- Своя точка входа: `python -m chatter.run`.
- Свои тесты: `tests/chatter/`.
- **Конфиги клиентов лежат ВНУТРИ пакета: `chatter/clients/<slug>/`.** НЕ в корневом `clients/` (там `clients/vera_ai_ua` — чужой image-продукт; при деплое на клиентский VPS его конфиг и бренд-стратегия не должны уезжать на чужое железо). Деплой на VPS = копирование одной папки `chatter/`.
- `--clients-dir` по умолчанию указывает на `chatter/clients/` (путь настраиваемый — на случай вынесенного контура конфигов).

## 2. Структура

```
chatter/
  requirements.txt
  run.py                 # CLI: --client, --transport, --clients-dir, --llm {real,fake}
  config/
    loader.py            # load+валидация persona/knowledge/playbook/settings → типизированный Config
  transport/
    base.py              # Transport ABC: receive(), send(text), send_typing(on|off)
    fake.py              # консольный транспорт с реальными таймингами
  core/
    llm.py               # LLMClient ABC + AnthropicLLM (claude-haiku-4-5) + FakeLLM (детерминированный)
    brain.py             # сборка промпта (persona+knowledge+playbook+история) → ответ; бюджет токенов
    humanizer.py         # ЧИСТЫЕ функции: read_delay, typing_duration, split_message, debounce
    disclosure.py        # ХАРДКОД честности; детектор вопроса «ты бот?»; формулировка из persona
    guardrails.py        # анти-выдумывание цен/сроков; флаг эскалации+лог; лимит/час; дневной кап
    conversation.py      # стейт-машина + факты + флаги; поверх storage
  storage/
    db.py                # один SQLite-файл; contacts, messages, facts, flags
  clients/
    demo/
      persona.md
      knowledge.md
      playbook.md
      settings.yaml
tests/chatter/           # TDD, зеркалит модули
```

## 3. Конфиг (настраиваемость = сам продукт)

- **persona.md** — имя, возраст, характер, манера речи, ключевые фразы, регистр.
- **knowledge.md** — товар, прайс, условия, FAQ.
- **playbook.md** — стадии воронки, цель каждой, триггеры эскалации, чего не обещать.
- **settings.yaml** — тайминги, модель, лимиты токенов/сообщений, `owner_id`, часы работы, `language`.

**Loader с валидацией:** битый/неполный конфиг → внятная ошибка `ConfigError` с именем файла и поля **при старте**, не в рантайме. Проверяет: наличие всех 4 файлов; непустые persona/knowledge/playbook; в settings.yaml — обязательные ключи и их типы/диапазоны (тайминги, лимиты, `owner_id`, `language ∈ {ru,en,uk}`, часы работы).

## 4. Humanizer (сердце продукта) — чистые функции, время инжектится

Все параметры из settings.yaml. Ни одна функция не спит — задержки возвращаются числом, реальный `sleep` только в транспорте/`run.py`. Тесты без sleep.

- **read_delay** — задержка чтения 1–5с (из конфига).
- **typing_duration(text, ...)** — печать 3–6 знаков/сек с разбросом ×0.8–1.4 (RNG инжектится/сидируется в тестах).
- **split_message(text, ...)** — разбиение длинного ответа на 2–3 сообщения с паузами между ними.
- **night_mode** — вне рабочих часов задержки больше (множитель из конфига; «сейчас» инжектится).
- **debounce/coalescing входящих (bot-tell):** окно 2–5с из settings.yaml. Входящие копятся; окно **продлевается** на каждое новое сообщение; по истечении — одна генерация на весь пакет. Живой прочитал бы оба и ответил один раз; бот, отвечающий на каждое мгновенно, палится. Заодно экономит токены.
  - Чистая логика решения: `debounce_ready(last_received_at, now, window) -> bool` и склейка пакета `coalesce(messages) -> str`. Накопление/ожидание — в цикле транспорта; **решение** — чистое и тестируется на инжектнутом времени.

Typing-индикатор пробрасывается через интерфейс транспорта (`send_typing`).

## 5. Brain

- Сборка промпта из persona + knowledge + playbook + история контакта.
- Стиль жёстко в системном промпте: 1–2 предложения; БЕЗ булитов/заголовков/корп-тона; задавать встречные вопросы.
- Дешёвая модель из конфига — `claude-haiku-4-5` (дефолт демо).
- Бюджет токенов на диалог.
- LLM за интерфейсом `LLMClient`. `AnthropicLLM` читает `ANTHROPIC_API_KEY`. `run.py` при отсутствии ключа падает на `FakeLLM`. **Юнит-тесты ВСЕГДА на `FakeLLM`** — ноль сети/трат. OpenAI можно добавить позже без правки brain.

## 6. Disclosure (ХАРДКОД, не в конфиге — тумблера быть не должно)

- Никогда не заявляет себя человеком.
- На прямой вопрос «ты бот/человек?» — честный ответ + мягкий перевод темы + предложение позвать владельца.
- **Формулировка** берётся из persona.md, но **факт честности не отключается** ничем.
- Детектор вопроса работает над входящим сообщением до/вокруг Brain.
- Тест: 10 формулировок вопроса → все дают честный ответ.

## 7. Guardrails

- Не выдумывать цены/сроки/скидки, которых нет в knowledge.md.
- Не знаю → флаг эскалации + лог (сама эскалация в арке 3; сейчас только флаг+лог).
- Анти-луп: лимит сообщений на контакт в час.
- Глобальный дневной кап сообщений.
- Числовой/keyword-детектор (`contains_unbacked_claim`) — это СТРАХОВОЧНАЯ СЕТКА, а не основная защита. Основная защита — системный промпт («не знаешь → не выдумывай, эскалируй»); сетка ловит только то, что промпт пропустил.

## 8. Conversation

- Стейт-машина: `new → qualifying → hot → escalated → closed / dead`.
- Извлечённые факты: что хочет, бюджет, возражения.
- Флаги: `paused`, `human_took_over`.
- SQLite (один файл), история по контакту.

## 9. Fake-транспорт + демо-прогон

- `python -m chatter.run --client demo --transport fake` → консольный диалог с реальными таймингами (видны задержки, разбиение, стиль, typing-индикатор, коалесцирование).
- `chatter/clients/demo/` — вымышленный бизнес: личный бренд, продаёт консультации и фотосессии (самый ходовой запрос). Язык демо: русский (`language: ru`), но `en`/`uk` поддержаны конфигом.

## 10. Язык

`settings.yaml: language` (демо `ru`; поддержаны `en`, `uk`) инжектится в системный промпт для усиления. Демо-файлы персоны написаны на русском.

## 11. TDD и Acceptance

TDD обязательно, тесты вперёд, зеркалят модули в `tests/chatter/`.

Acceptance:
1. `python -m chatter.run --client demo --transport fake` → веду диалог в консоли, вижу задержки/разбиение/стиль/коалесцирование.
2. Меняю 5 строк в `persona.md` → бот отвечает как другой человек.
3. Прямой вопрос «ты бот?» → честный ответ.
4. Вопрос про цену, которой нет в `knowledge.md` → не выдумывает.
