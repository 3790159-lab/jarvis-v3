## 1. Ответ: лестница из шести уровней

`_answer(fast, slow_cache) -> Answer(text, tone, second_line, level)`.
Порядок = приоритет, **первый сработавший выигрывает**, остальные не считаются —
идиома клиентской панели («немає зв'язку перебиває чергу»).

| # | Уровень | Условие | Ответ (32 px) | Тон |
|---|---|---|---|---|
| L1 | Панель не видит правды | `psutil` недоступен; быстрые источники не прочитались | «Не бачу ферму» | broken |
| L2 | Деньги встали | процесс `chatter` = bad | «Ліди без відповіді» | broken |
| L3 | Упало то, что само не встанет | процесс bad **и** его гардиан не ok | «Впало: {N}, само не підніметься» | broken |
| L4 | Сторожа врут | гардиан `warn` (расхождение) или плановая задача не-ok | «Сторож каже одне, система інше» | wait |
| L5 | Ключ истекает | `days_left < 7` | «Ключ {name}: {N} дн» | wait |
| L6 | Всё цело | иначе | «Ферма ціла» | calm |

**Два условия НЕ поднимаются в ответ, и это решение, а не недосмотр:**

- **«Внешний сторож не настроен»** (`external.bad`) — оно истинно всегда и не
  меняется. Ответ, который не меняется, перестаёт быть ответом: это ровно тот
  вечно-красный, из-за которого красный теряет смысл. Остаётся строкой `.note`
  под ответом, как сейчас.
- **`⚠️` в заметке ключа** («FAL_KEY потребує ротації») — то же самое: висит
  месяцами, живёт в аномалиях, но ответ не занимает. В ответ ключ попадает
  только сроком (L5).

**Процесс bad при живом гардиане — это НЕ L3.** Он даёт L6 или L4, а факт
падения уезжает во вторую строку. Вчера в 00:45 было именно так: раннер упал,
гардиан поднял за 61 секунду. Сегодня оба случая дают одинаковое «Впало: 1» —
это главная потеря смысла в нынешнем ответе.

### 1.1. Вторая строка: «само поднимется / не поднимется»

Нужна связь процесс ↔ гардиан, которой в коде **сейчас нет вообще**. Добавляется
одной константой рядом с `PROC_SPECS`/`GUARDIAN_SPECS`:

```
PAIRS = {"backend": "backend_guardian", "bot": "bot_guardian", "chatter": "chatter_guardian"}
```

(`ops_watchdog` пары не имеет — он сторожит сторожей.)

| Ситуация | Вторая строка |
|---|---|
| процесс bad, гардиан ok | «підніметься сам: {guardian} живий, ~{ETA} с» |
| процесс bad, гардиан warn/bad | «сам не підніметься: {guardian} — {detail}» |
| гардиан bad, процесс жив | «якщо впаде — підняти нікому» |
| L1 | «стан нижче не читай — він зібраний наполовину» |
| L6 | «перевірено: 3 процеси, 4 гардіани, {N} задач» |

ETA берётся из констант гардианов, а не из головы: chatter и bot —
`IntervalSeconds=30 × DebounceFailures=3` ≈ **90 с**, backend —
`IntervalSeconds=15`. Числа дублируются в питоне и в PowerShell, поэтому рядом
с `PAIRS` ставится комментарий с путём к скрипту-источнику: разъедутся —
соврёт вторая строка, а не упадёт код.

## 2. Аномалия против состояния

Единственная точка решения — `is_anomaly(kind, item) -> bool`. Пороги —
именованные константы модуля, не литералы по коду:

```
KEY_EXPIRY_ANSWER = 7     # в ОТВЕТ (L5)
KEY_EXPIRY_ANOMALY = 30   # в блок аномалий
HEARTBEAT_FRESH = 90      # уже есть
SLOW_MAX_AGE = 300        # медленный кэш старше — секция помечается протухшей
```

| Аномалия (первый экран, развёрнуто) | Состояние (свёрнуто) |
|---|---|
| процесс `bad` | процесс `ok` + PID + дата старта |
| гардиан `warn`/`bad` | гардиан `ok` + «heartbeat 12 с тому» |
| задача не-ok, **кроме** `RETIRED` | Ready/Running с результатом 0 / 267009 |
| `external` не-ok | `RETIRED` (снайпер) — класс «отставлено», не жёлтый |
| ключ `days_left < 30` или `⚠️` в заметке | ключи без срока и без ⚠️ |
| worktree `dirty` (грязное дерево слепит гейт) | `merged`, `age_days` по 21 ветке |
| — | лента событий целиком |

Тест принадлежности один: **изменит ли это моё поведение в ближайший час?**
`age_days` растёт сам собой — это не событие. «heartbeat 12 с тому» меняется на
каждый запрос, а смысл не меняется ни разу.

**Разметка:** аномалии — обычные `.card`; состояние — в родном `<details>`
(ноль JS, `.more>summary` в CSS уже есть) с суммой в `<summary>`:
«Стан: 3 процеси, 4 гардіани, {N} задач, {N} гілок, 6 ключів». Свёрнуто по
умолчанию на узком, развёрнуто вторым столбцом на широком (§4).

## 3. Быстрый и медленный сбор

Сейчас `snapshot()` собирается **6.8 с** синхронно на каждый заход. Первый
экран не имеет права этого ждать.

| Класс | Что | Стоимость | Кто ждёт |
|---|---|---|---|
| **FAST** | `processes`, `guardians`, `external` | миллисекунды (psutil + два `stat`) | первый экран |
| **SLOW** | `tasks` (PowerShell), `arcs` (git × 21), `events`, `keys` | секунды | никто |

- Ответ L1–L4 и L6 считается **только по FAST**. L5 (ключи) и «задачи» в L4
  участвуют, **только если медленный кэш свежий**; иначе уровень пропускается,
  а под ответом печатается «задачі та ключі ще не зчитані» — не молчание.
- Медленное отдаётся отдельной ручкой `/panel/jarvis/slow` (тот же роутер, тот
  же `require_owner`), страница дозагружает её `fetch`'ем — приём уже
  используется на клиентской панели. Фоновых потоков не заводим: это была бы
  новая сущность.
- Кэш медленного — в памяти процесса, TTL 300 с. Совпадает с тем, что уже
  предлагалось в PHASE0 §9 («ферма — 30 с, арки/ключи — 5 мин»).
- **Два возраста на экране, не один:** «ферма зібрана 2 с тому · арки, ключі,
  задачі — 4 хв тому». Одна общая подпись соврёт ровно тогда, когда медленный
  сборщик встанет.
- Сторож: `panel()` рендерится и даёт ответ, **когда `arcs()` и
  `scheduled_tasks()` бросают исключение или висят**. Сегодня это уронило бы
  страницу целиком.

## 4. Fold: две раскладки на существующих брейкпоинтах

Новых брейкпоинтов не вводим — берём те, что уже в `panels_ui.CSS`.

| Ширина | Раскладка |
|---|---|
| ≤ 620 px (внешний экран Fold, телефон) | один столбец: ответ → вторая строка → `.note` внешнего сторожа → аномалии → `<details>` состояние. Таблицы уже превращаются в карточки (`data-l`) |
| 620–760 px | тот же один столбец, таблицы таблицами |
| ≥ 760 px (развёрнутый Fold, ноут) | два столбца: слева ответ + аномалии, справа состояние **развёрнутым** |

Ключевое: **разметка одна**, порядок DOM = порядок важности, широкая раскладка
только раскладывает тот же DOM гридом (`@media(min-width:760px){.two{display:grid;
grid-template-columns:1.2fr .8fr;gap:14px}}`). Дублировать блоки под два экрана
нельзя — два экрана разъедутся на первой же правке.

Порог 760 взят потому, что он уже существует (плитки 4→2). Если внутренний
экран Fold в браузере даёт меньше 760 CSS-пикселей, он попадёт в одноколоночную
раскладку — см. вопрос §8.1.

## 5. Место под «поки тебе не було»

- Слот — **одна строка сразу под второй строкой ответа**, класс `.note`.
- В заходе 1 она **не рендерится вообще**. Не пустая рамка, не «подій немає»:
  пустой слот читается как «ничего не случилось», а мы этого не знаем — знать
  будет заход 2.
- Контракт для захода 2 (фиксируется сейчас, чтобы вёрстку не переделывать):
  строка появляется, только когда есть журнал И известен `last_seen`; текст —

## 6. Заход 2 зафиксирован, здесь НЕ делается

Записано, чтобы заход 1 не спроектировали так, что журнал некуда вставить.

1. **Сначала `ts` в `events()`** — строки гардианов несут время текстом
   (`2026-08-14 00:44:08 | runner DOWN`), а код ставит `ts: None`. Без времени
   слой не строится.
2. **Писатель — `ops_watchdog`** (живой, ходит по расписанию). Панель только читает.
3. **Закрытый список переходов, не diff снапшота** (иначе шумят PID, `hb_age`,
   `age_days`).
4. **`state/panel_last_seen.json` по владельцу, не cookie** — браузеров четыре.
5. **`seen_at` на событии**, метка двигается по явному «прочитано», а не по
   факту открытия страницы.
6. Плюс два дефекта ленты: чтение `control_events` из **демо-базы** вместо живых
   клиентов и окно в 40 строк лога с молчаливой ротацией.

Действия (вариант B, «ткнуть гардиана») — **после** журнала: каждое нажатие
обязано в него писаться.
