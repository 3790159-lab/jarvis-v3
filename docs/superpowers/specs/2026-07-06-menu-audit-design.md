# Спека: Арка «Ревизия» — аудитор меню (menu-audit)

**Дата:** 2026-07-06
**Ветка:** phase-4.0-unified-jarvis
**Мотив:** живой краш `/browse_check` — `NameError: name 'os' is not defined` (сессия
browse_35e7ad9a). Баг сидел в теле функции с `# pragma: no cover` (live money-gated
path), поэтому ни один тест его не гонял и голый `import` его не ловил. Нужен
сторож, который физически не пускает **класс** таких багов на прод по **всем**
командам меню.

**Статус:** черновик на утверждение. Реализации нет. `спека → СТОП → ОК → код`.

---

## 1. Цель и не-цель

**Цель.** Автономный аудитор, который проходит по всему реестру команд меню
(`tools/jarvis_menu.py::MENU`, 11 категорий / 110 пунктов) и для каждой команды
отвечает: **жив / сломан / мёртв** — с причиной. Ловит ровно класс
`/browse_check`-бага (пропущенный импорт, используемый внутри тела функции) и
«висячие» пункты меню без хендлера.

**Не-цель (YAGNI, вырезано осознанно):**
- НЕ вызывать money- и side-effect-команды (генерации, рестарты, git-write,
  отправки во внешние сервисы). Для них — только импорт + наличие хендлера.
- НЕ проверять корректность бизнес-логики хендлеров (это не тест-сьют по существу).
- НЕ admin-команда `/audit` сейчас — в бэклог как будущая dev-задача.
- НЕ аудит non-menu команд (`/start`, `/browse_watch_stop`, `/browse_status`…) в v1
  — источник истины = `MENU`. (Врезка про это в §7, риск R3.)

## 2. Три оси проверки (решения из брейнсторма)

| # | Ось | Метод (утверждён) | Что ловит |
|---|-----|-------------------|-----------|
| A | **Хендлер существует** | Статический **AST-разбор** `handle_command` (if/elif) | «мёртвые» пункты меню без ветки диспетча |
| B | **Импорты живые** | **Глубокий LOAD_GLOBAL-скан** (импорт модуля + дизассемблер каждой функции) | `/browse_check`-класс: имя используется в теле функции, но не импортировано |
| C | **Dry-вызов где безопасно** | **Курируемый read-only allowlist** (см. §5), прогон через `handle_command` с перехватом `send` | что даже заведомо-безопасная команда реально отрабатывает, а не «unknown»/исключение |

Динамический пробинг через `handle()` для оси A **отвергнут** (риск side-effects).
Ось C ограничена жёстким allowlist — всё вне списка не вызывается никогда.

### 2A. Ось A — модель роутинга (детали AST)

`handle_command(chat_id, cmd, query, state)` — большая if/elif-цепь без реестра.
Экстрактор собирает множество «маршрутизированных» команд из AST функции:

- `cmd == "/x"` и `"/x" == cmd` → литерал `/x`;
- `cmd in ("/a", "/b", …)` → все литералы кортежа/множества;
- `cmd.startswith("/prefix")` → **префиксное правило**: любой пункт меню,
  начинающийся с `/prefix`, считается маршрутизированным (иначе `/swapbatch_set_quality`
  дал бы ложную «мёртвую»).

**мёртв** = пункт `MENU`, не покрытый ни точным литералом, ни префиксным правилом.
AST-разбор идёт по **исходнику** (`ast.parse`), **без импорта** control-файла на
этой оси → ноль side-effects.

### 2B. Ось B — глубокий LOAD_GLOBAL-скан

Обобщение зуба `tests/test_browser_imports_smoke.py` (написан сегодня под
`/browse_check`-фикс) на весь набор хендлер-модулей:

1. `import` модуля без моков — падение здесь = **сломан (import-time)**.
2. Для каждой функции модуля дизассемблировать (`dis`) и собрать все `LOAD_GLOBAL`;
   каждое имя обязано резолвиться в `vars(module)` **или** `builtins`. Рекурсия в
   вложенные code-объекты (comprehensions, замыкания). Непокрытое имя = **сломан
   (undefined-global)** с точной локацией `module:function:name` — это и есть
   `os`-баг.

**Набор сканируемых модулей (v1):** `tools.jarvis_menu`,
`tools.jarvis_smart_telegram_control` (главный хендлер-файл), и весь пакет
`app.services.**` (рекурсивный обход `pkgutil`). Control-файл импортируем — он
import-safe (существующий `test_browser_commands.py` уже импортирует его на верхнем
уровне; все `.start()` — внутри функций, run под `if __name__=="__main__"`).

Скан — **проектного уровня**, не строго per-command: результат оси B = список
битых модулей/функций. Привязка к команде: если undefined-global найден в функции,
чьё имя = хендлер конкретной команды (напр. `_default_run_agent` в цепочке
`/browse_check`), — атрибутируем команде; иначе отражаем в модуль-секции отчёта.
Практически: **любой** хит оси B заваливает регресс-зуб (§6), даже без точной
привязки к пункту.

## 3. Критерии статуса (крепко)

| Статус | Условие |
|--------|---------|
| 🟢 **жив** | ветка хендлера есть (A) **И** все затронутые модули импортируются + ноль undefined-globals (B) **И** (если в allowlist) dry-вызов вернулся без исключения и без «unknown»-сентинела (C) |
| 🟡 **сломан** | ветка есть (A=ok), но: модуль не импортируется, ИЛИ undefined-global в функции (B), ИЛИ allowlist-dry-вызов упал/вернул «unknown» (C) |
| 🔴 **мёртв** | пункт `MENU` без ветки в диспетче (A=fail) — пользователь провалится в unknown/разговорный фолбэк |

Приоритет тяжести в отчёте: 🔴 → 🟡 → 🟢.

## 4. Выход (форма)

Две поставки (обе утверждены):

### 4.1 CLI-диагност `scripts/audit_menu.py`
Печатает подробную таблицу в stdout **и** пишет markdown-снимок в
`state/menu_audit_report.md` (state/ в .gitignore — снимок не коммитим, как
`regress_baseline.json`). Колонки: `команда | категория | роль | статус | ось-провала | причина`.
Внизу — сводка `N жив / M сломан / K мёртв` и полная секция оси B (модуль:функция:имя).

**Порядок отчёта:** первыми идут категории **🌐 Браузер** и **🛠 Разработка**
(самый свежий код — там сегодня и стрельнуло), затем остальные в порядке `MENU`.
Exit-code: `0` если 0 мёртвых и 0 битых импортов; `1` иначе (для CI/ручного гейта).

### 4.2 Pytest-регресс-зуб `tests/test_menu_audit.py`
Сторож в общем регресс-гейте:
- `test_no_dead_menu_commands` — множество `MENU` cmd ⊆ маршрутизированных (A).
- `test_no_undefined_globals_in_handler_modules` — ось B по всему набору = пусто.
- `test_allowlist_commands_execute_cleanly` — каждая allowlist-команда (C) отрабатывает.

Падает при мёртвой команде / битом импорте / undefined-global → класс
`/browse_check`-бага **физически не доезжает до прода** через регресс-гейт.

Общая логика (сбор реестра, AST-роутинг, LOAD_GLOBAL-скан, dry-harness) живёт в
`app/services/audit/menu_audit.py` (чистые функции, $0, тестируемо); скрипт и тест —
тонкие обёртки над ней.

## 5. Read-only allowlist для dry-вызовов (ОТДЕЛЬНЫЙ БЛОК НА УТВЕРЖДЕНИЕ)

Правило: dry-вызывается **только** то, что заведомо бесплатно и без записи/сети-в-мир.
Всё остальное — только оси A+B. Прошу пройтись и вычеркнуть спорное.

### Tier A — ядро (по умолчанию ВКЛючено; чистые статические списки/справка/локальное чтение)
| Команда | Почему безопасно |
|---------|------------------|
| `/me_roles` | отдаёт статический список ролей, без I/O |
| `/me_places` | статический список мест |
| `/me_styles` | статический список стилей |
| `/dish_styles` | статический список стилей подачи |
| `/party_themes` | статический список тем |
| `/capabilities` | перечисляет возможности, без I/O |
| `/my_stats` | читает локальный леджер (read-only, бесплатно) |
| `/menu` | рендер каталога (чистые функции `jarvis_menu`) |

### Tier B — пограничные (по умолчанию ВЫКЛючено; read-only, но трогают subprocess/сеть/backend — включаем по-строчно по твоему решению)
| Команда | Оговорка |
|---------|----------|
| `/git_status` | git-**чтение** (subprocess `git status`), без записи |
| `/logs_tail` | чтение хвоста лог-файла |
| `/health` | может пинговать backend :8010 (сеть, бесплатно) |
| `/smart_health` | health-агрегат (сеть к провайдерам, бесплатно) |
| `/status` | статус AI-провайдеров (сеть, бесплатно) |
| `/costs` | чтение леджера трат |
| `/stats` | чтение леджера |
| `/agents` | статус агентов (может дёргать backend) |

### Чёрный список (НИКОГДА, даже если «выглядит» read-only) — только оси A+B
Всё из `_VIDEO`/`_PERSONA`/`_ME`(генерации)/`_PHOTO`/`_APPS`, любые `*_go`,
`/faceswap`, `/enhance`, `/animate*`, `/persona_*`, `/create_*`, `/train_lora`,
`/restart_backend`, `/restart_bot`, `/regress` (гоняет тесты — тяжело),
`/clear`, `/cancel*`, `/figma_clear`, `/night_now`, `/improve`, всё с отправкой/записью.

Харнесс C: сохранить/подменить `mod.send` (и любые внешние отправки) на перехват,
собрать минимальный `state`, вызвать `mod.handle_command(fake_chat, cmd, "", state)`,
проверить: не поднялось исключение и перехваченный ответ не содержит «unknown»-сентинел.
Восстановить патчи в `finally`.

## 7. Допущения и риски

- **R1 — AST-роутинг неполон.** Если диспетч использует экзотический паттерн
  (словарь-делегатор, `getattr`, вычисляемые имена) — экстрактор может дать
  ложно-мёртвую. Митигация: поддержать `==`/`in`/`startswith`; на ложняках —
  явный «known-router» whitelist в модуле аудита с комментарием. На старте
  диспетч — простой if/elif, риск низкий.
- **R2 — импорт control-файла.** Считаем import-safe (доказано существующим
  тестом). Если появится import-time side-effect — ось B по control-файлу
  переводим на статический AST-анализ undefined-names (без импорта); заложить как
  fallback, не реализовывать заранее (YAGNI).
- **R3 — non-menu команды вне охвата.** `/browse_watch_stop`, `/browse_status`,
  `/start`, `/help` не в `MENU` → не аудируются в v1. Если нужно — отдельный явный
  `EXTRA_COMMANDS` список во второй итерации.
- **R4 — dry-harness state.** Некоторым read-only хендлерам нужен непустой `state`.
  Для allowlist-команд собираем минимальный валидный state; если команда требует
  контекст, которого нет — помечаем `C: skipped (needs context)`, статус остаётся
  по A+B (не заваливаем).
