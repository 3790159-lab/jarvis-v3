# CHATTER-3A-UX — Человеческая адресация (под-арка 3A)

**Дата:** 2026-07-17
**Статус:** принята к реализации
**Предыдущее:** 3A (перехват + пульт) — код готов, дрил пройден, 312 тестов, ветка `chatter-arc3a`, СТОП перед мерджем.
**Эта под-арка:** убрать голые id из интерфейса. Владелец знает клиентов по именам, а не по числам.

---

## 0. Зачем — находка живого дрила

3A прошла дрил функционально: перехват сработал, пауза встала, `/resume` вернул Аню. И тут же вскрылась дыра, которую **не мог поймать ни один тест**, потому что все они проверяли ПОВЕДЕНИЕ, а провалился ИНТЕРФЕЙС:

> Карточка говорит «⏸ Пауза: 237616472». Оператор: «Я не знаю своих клиентов по id — я знаю их по именам. Возобновить диалог оказалось очень сложно, я даже не знаю как это сделать».

**Это блокер продажи, а не косметика.** Систему строил сам оператор — и не разобрался. Предприниматель, купивший продукт, не разберётся тем более. Он купил инструмент, а не курс по нему.

**Критерий приёмки — не «команды работают», а «владелец возобновил диалог, ни разу не увидев числа».**

## 1. Правила

**НИ ОДНОГО ГОЛОГО ID В ИНТЕРФЕЙСЕ.** Везде — имя + `@username`. Числовой id — только fallback, когда у человека нет ни имени, ни юзернейма (бывает). Имя кликабельно: тап открывает диалог.

**КОМАНДА ЛЕЖИТ В ВЫВОДЕ.** Владелец не сочиняет команду, а копирует её глазами из `/status`. Это разница между «пультом» и «квестом».

**ЯЗЫК ИЗ `settings.yaml`** (`ru`/`en`/`uk`), как у честности (`disclosure.honest_disclosure`). Клиент-англичанин не читает русский пульт.

## 2. Целевой вид `/status`

```
⏸ Паузы (2):
1. Даниил Лапин (@lapin) — вы вмешались 6 мин назад
   «Может вы ещё что-то хотели бы обсудить?)»
   → /resume 1
2. Вася Иванов — /pause 1h, осталось 42 мин
   → /resume 2
🟢 Бот активен · авто-возврат: прогон 12с назад
```

Имя — кликабельная ссылка. Команда — прямо под строкой.

## 3. Номера: адресация без чисел-идентификаторов

Номер (`1`, `2`) — это НЕ id. Это порядковый ярлык из последнего `/status`, который владелец видит глазами и копирует.

**Номера привязываются к контакту В МОМЕНТ ВЫДАЧИ и хранятся в таблице** `status_index(n PK, contact_id, issued_ts)`, переписываемой целиком на каждый `/status`. Переживают рестарт — как `console_cards`.

**Почему привязка, а не пересчёт «на лету»:** если номера пересчитывать от текущего списка, то сценарий «посмотрел `/status`, отвлёкся, Даниил авто-вернулся, набрал `/resume 1`» попадёт в Васю — в ЧУЖОЙ диалог. Оператор назвал это верно: промах в чужой диалог = катастрофа доверия. Привязка в момент выдачи делает промах невозможным: `1` навсегда означает того, кого владелец видел под единицей.

**Устаревший список.** Привязка защищает от промаха, но не от рассогласования картины мира: если владелец смотрел `/status` час назад, а список с тех пор изменился, он метит не в тот диалог, который имеет в виду. Поэтому:

- номера нет в таблице → «нет такого номера, набери /status»;
- **набор заглушённых контактов отличается от снимка** → «список устарел, набери /status» + НЕ выполнять;
- набор совпал → номера значат ровно то же, что видел владелец → выполняем.

Сравнение НАБОРОВ (а не TTL) точнее: TTL — это гадание про «сколько минут доверия», а набор отвечает на настоящий вопрос — «тот ли это список, который он видел».

## 4. Пути адресации (три, по убыванию удобства)

1. **Реплай на карточку** — основной, уже работает в 3A. Карточка лежит в Saved Messages, владелец отвечает на неё `/resume`.
2. **Номер из `/status`** — для случая «карточка уехала вверх».
3. **`/resume <@username | ссылка | id>`** — fallback, остаётся.

## 5. Карточка паузы

Имя вместо id, кликабельная ссылка на диалог, и подсказка в ДВЕ строки — потому что на дриле выяснилось, что одной мало:

```
⏸ Пауза: Даниил Лапин (@lapin)
Вы вмешались: «Может вы ещё что-то хотели бы обсудить?)»
Аня молчит в этом диалоге.

Ответьте /resume на это сообщение
или: /status → /resume <номер>
```

## 6. `/help`

Полный список команд, примерами, человеческим языком, для того, кто видит пульт впервые. Не справка по API — объяснение, что вообще происходит и как вмешаться.

## 7. Технические решения

**Разметка.** Кликабельные имена требуют `parse_mode`. Берём **HTML** и **экранируем `html.escape()` ВСЁ подставляемое**: `detail` — это дословный текст владельца, он может содержать `<`, `&`, `"`. Неэкранированный текст либо развалит разметку, либо подделает её. Это тот же класс, что уже ловили в 3A с переводом строки в `detail`, только злее: там ломалась вёрстка, здесь ломается парсер Telegram и сообщение не уходит вообще.

**Ссылка:** `t.me/<username>` если юзернейм есть, иначе `tg://user?id=<id>` (работает, пока entity в кэше сессии — а он там есть, раз мы только что через него общались).

**Имя:** `first_name + last_name` → если пусто, `title` (для каналов) → если пусто, `@username` → если пусто, `id` как последний fallback. Голый id в интерфейсе — признак того, что о человеке не известно НИЧЕГО, а не норма.

**i18n:** словарь строк на язык, по образцу `disclosure.py`. Ключи — по смыслу (`status_header`, `resume_hint`), не по тексту.

## 9. Тесты

- Ни один рендер не содержит голого id, если есть имя или юзернейм (главный тест под критерий приёмки).
- Fallback-цепочка имени: имя → юзернейм → id.
- `html.escape` для `detail` с `<`, `&`, `"` и с переводом строки.
- Номер привязан к контакту: снимок выдан → контакт авто-вернулся → `/resume 1` метит в ТОГО ЖЕ, а не в соседа по списку.
- Набор изменился → «список устарел», действие НЕ выполнено.
- Номера переживают рестарт (новый `Store` на том же файле).
- `/help` содержит все команды, на трёх языках.
- Язык берётся из `settings.yaml`.

**Живой дрил:** оператор возобновляет диалог, ни разу не увидев числа. Это и есть приёмка.

## 10. Не входит

Кнопки (требуют второго `getUpdates` — см. 3A §7), поиск по имени (`/resume Даниил` — двусмысленно при тёзках), веб-дашборд.
