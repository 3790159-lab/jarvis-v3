**Цель:** доказать фактом, что общий промт уже работает, и зафиксировать baseline «мультяшности».

**Шаги (живой тест, бот):**
1. `/swapbatch_set_prompt <мой текст>` → одно видео (5с/720p) → убедиться, что применился **мой** промт, не дефолт.
2. Сохранить это же видео как **baseline** для сравнения на Этапе 1 (текущие настройки: `prompt_expansion=on`, `negative=""`).

**Готово когда:** подтверждено, что мой промт применяется ко всем; есть baseline-видео.
**Если промт НЕ применяется** → это баг, чинится в рамках Этапа 0 (мелкая правка проброса `motion_prompt`).
**Трата:** ~$0.30. **Страховка:** один файл, не масса.

## Этап 1 — Реализм + лимит промта

**Цель:** убрать анимешность/мультяшность; не молчать на длинном промте.

### 1a. Анти-аниме (твой #2)
**Изменения:**
- `wavespeed_spicy_engine.py`: вынести `enable_prompt_expansion` из хардкода в параметр (default из конфига); пробросить `shot_type` если зададим.
- Дефолтный `negative_prompt` (где резолвится дефолт промта, бот-слой): `"anime, cartoon, illustration, 2d, drawing, painting, render, doll, plastic skin"`.
- Дефолтные добавки в промт: `"photorealistic, realistic, cinematic, natural skin texture, detailed skin"`.
- Кастомный промт пользователя НЕ перетирается — добавки/negative применяются поверх, промт остаётся ведущим.

**Тест (дешёвый, порядок по решению пользователя):**
1. Вариант A: `prompt_expansion=off` + negative (5с/720p, ~$0.25).
2. Вариант B (если A мало): + добавки в промт.
3. (опц.) `shot_type=single` vs `multi`.
Сравнить с baseline Этапа 0 → выбрать настройки → закрепить как дефолты.

**Готово когда:** выбранный вариант заметно реалистичнее baseline; дефолты зашиты.
**Трата:** ~$0.25 × 2–3 варианта. **Страховка:** маленький тест, **живой тест — стоп, зову пользователя** перед массой.

### 1b. Лимит символов промта (твой #4)
**Изменения:**
- Узнать лимит WaveSpeed wan-2.6 (research / пробный запрос с длинным промтом).
- Валидация в `handle_set_prompt()` / перед отправкой: если промт длиннее лимита → **предупредить пользователя** (сколько символов, какой лимит) и предложить обрезать, либо обрезать с уведомлением. **Не молчать.**

**Готово когда:** длинный промт даёт явное сообщение, а не тихий сбой.
**Трата:** ~$0 (валидация локальная).

**Цель:** второй движок + меню выбора после свапа + standalone `/animate`.

**Изменения:**

**Готово когда:** оба движка работают через меню; `/animate` гонит одиночное видео; биллинг считает оба.

## Этап 3 — UX-кнопки длины/качества (твой #3)

**Цель:** заменить `/swapbatch_set_quality duration=10 resolution=720p` на тапаемые кнопки.

**Изменения:**
- Inline-клавиатура: ряд длины (5/10/15 — фильтр по caps движка), ряд качества (720/1080), кнопка «Готово».
- Callback (`swq:` префикс) → собирает строку `duration=.. resolution=..` → существующий `handle_set_animate_quality()`. Логику не дублируем, оборачиваем.
- Кнопки уважают caps выбранного движка (Seedance: нет 15с; WaveSpeed: нет 480p).

**Готово когда:** длину/качество можно задать тапами; команды остаются как fallback.
**Трата:** $0 (UI-обёртка). Ставим последним — оборачивает уже финальную логику движков.

## Сквозные страховки (все этапы с тратами)

- Концентрация животных запросов ≤ 2 (`SWAPBATCH_ANIMATE_CONCURRENCY`).
- Money-safe retry (как в Фазе A).
- Маленький тест (1 видео) перед массой.
- **Живой тест на боте = СТОП, зову пользователя** перед запуском.
- Флаг `SWAPBATCH_ANIMATE_ENABLED` остаётся рубильником.
- Все траты — дешёвый профиль (5с/720p) до подтверждения.

## Вне области (YAGNI сейчас)

- Авто-детекция NSFW для гейтинга Seedance (решено: только пометка).
- Per-photo выбор движка (движок — на батч).
- RIFE fps-интерполяция > 21 (отдельный флаг, не трогаем).
