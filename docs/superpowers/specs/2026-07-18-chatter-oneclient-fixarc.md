## H1 — СЕТЬ ОБЯЗАТЕЛЬСТВ (главное). Два слоя, оба по ОТВЕТУ Ани.

Урок аудита: промпт запрещал скидку, Аня дала → нужен КОД, не правило.

### Слой 1 — детерминированная term-сеть (новый чистый модуль `chatter/core/obligations.py`, зеркало `brand_safety.py`)
`unbacked_promise(reply, knowledge, promise_terms) -> str | None` — возвращает первый стем-обещание, который:
- (a) есть в ОТВЕТЕ Ани (casefold-подстрока/стем),
- (b) НЕ отрицается рядом (гард против «скидок нет», «рассрочку не делаем», «без гарантий», «гарантий не даю» — честные отказы НЕ трогаем),
- (c) НЕ обеспечен knowledge (если стем есть в knowledge — клиент реально это предлагает, не флагуем).

Дефолт `promise_terms` (per-client в settings.yaml, как `forbidden_terms`, с дефолтом на ru+uk):
`скидк, знижк, гаранти, гаранту, рассрочк, розстрочк, бесплатн, безкоштовн, подар, исключени, виняток, договорим, домовим, обещаю, обіцяю, гарантир, перезвон, передзвон, свяжус, свяжет, зв'яжус, зв'яжет, созвон`.

Wiring: новый тег `unbacked_promise` в `escalation.deterministic_escalation` (по ОТВЕТУ, рядом с `unbacked_claim`). Порядок: после brand-safety/keyword, до/рядом с unbacked_claim.

## H2 — «Дмитрий свяжется» контингентно доставке карточки
Причина↔следствие: карточка НЕ ушла → Аня НЕ обещает контакт (говорит то, что может сама).
- `_post_escalation_card` возвращает `delivered: bool` (handle не None).
- `promises_human_contact(reply)` — helper (подмножество term-сети: свяжет/перезвон/созвон/«владелец … свяжется»).
- В `_escalation_pass`: если ответ обещает человеческий контакт → эскалируем (горячий сигнал) и решаем финальный ответ ПОСЛЕ карточки: `delivered=True` → оставить (владелец узнал); `delivered=False` или эскалация не сработала → подменить на само-действие Ани («передам владельцу и вернусь к вам» — то, что Аня выполнит сама, без обещания за третье лицо).
- Порядок в `_escalation_pass` переставить: для human-contact-ветки пост карточки → затем фиксация reply.
