# Grok video→swap arc — карта этапов (СПЕКА, не код)

**Дата:** 2026-06-26 · **Статус:** карта на согласование, код после ОК
**Контекст:** [[jarvis-grok-uncensored-vision-target]], [[jarvis-motion-prompt-ai-arc]], [[jarvis-per-video-prompts-arc]], [[jarvis-video-animate-wavespeed-state]]

## Цель (подтверждена Daniil вручную)
Видео-референс → Grok анализ → **лучший кадр для свапа** + **промт, воспроизводящий движение из видео** → свап лица → видео с тем же движением.

## Почему Grok
Claude Vision цензурит спайси-контент Daniil by design (живой тест: `layer=1` реальный отказ). Grok (xAI) — uncensored, проверен вручную. xAI OpenAI-совместим (`openai` SDK 2.33.0 стоит, `base_url=api.x.ai/v1`, model `grok-4.3`, key `XAI_API_KEY`, ~1¢/вызов).

## Что переиспользуем (НЕ пишем заново)
- **Money-обвязка:** `cost_tracker` + `check_limit`/`record_cost` (gate ДО платного вызова, charge ПОСЛЕ успеха).
- **Friend-гейт:** `FRIEND_ALLOWED_CALLBACK_PREFIXES`, лимиты друга.
- **Refusal-детекция:** `_refusal_layer` — чистая текст-функция, **движок-агностична**, переиспуема как есть.
- **FaceValidator (InsightFace buffalo_l)** — уже в стеке, годится для скоринга кадров (Этап 4).
- **Свап:** `SwapEngine`/`/swapbatch`. **Анимация:** двухдвижковый video-maker (WaveSpeed/Seedance) из Этапа 2.
- **custom_prompts / per-video промты** ([[jarvis-per-video-prompts-arc]]) — слот под промт движения.

## Этап 0 — Spike: живой коннект к Grok (ПРЕДУСЛОВИЕ, крошечный)
Проверить `XAI_API_KEY` присутствует+валиден; один реальный vision-вызов `grok-4.3` с base64-картинкой; убедиться в формате ответа (shape, encoding image как `image_url` data-URI vs base64-block).
- **Объём:** XS (полчаса, ручной smoke-скрипт). · **Риск:** LOW, но блокирует всё — без живого подтверждения формата API остальное на песке. · **Зависимости:** ключ в `.env`.

## Этап 1 — Grok vision-клиент (новый модуль)
По образцу OPENAI_COMPAT: `openai`-клиент c `base_url` xAI, `grok-4.3`, `XAI_API_KEY`. Методы: `is_vision_supported()` (ключ есть), `analyze_image(path, q)`, **`analyze_images([paths], q)`** (xAI берёт пачку кадров без лимита). Refusal-детекцию НЕ дублируем — `_refusal_layer` зовётся на выходе (engine-agnostic).
- **Объём:** S–M (1 модуль, TDD на моках openai-клиента; новизна = multi-image метод). · **Риск:** LOW (SDK стоит, совместимость), остаточный = квирки xAI (auth/encoding/response) — снимается Этапом 0. · **Зависимости:** Этап 0.

## Этап 2 — Grok как vision-движок для ✨ (фото→промт) ← БЫСТРАЯ ПОБЕДА
Провайдер-свитч (`MOTION_VISION_PROVIDER=grok|claude`, дефолт grok для motion): `generate_motion_prompt` зовёт Grok вместо Claude. Проверяет ВСЮ интеграцию (money-safe + friend + refusal) на реальной кнопке ✨ с контентом Daniil. Возможна лёгкая подстройка MOTION_VISION_QUESTION под формат вывода Grok (comma-list).
- **Объём:** S (индирекция + флаг + тесты). · **Риск:** LOW–MED (валидирует live; Claude остаётся fallback). · **Зависимости:** Этап 1.
- **Это и есть мгновенный анблок исходного провала ✨** (Claude-цензура).

## Этап 3 — Нарезка референс-видео на кадры (ИНФРА-вопрос)
Нужен intake видео в боте (не фото) + извлечение кадров. ffmpeg локально НЕТ, cv2 локально не импортится.
- **Варианты:** (a) поставить статический ffmpeg локально + в PATH — простейший one-time; (b) резать на поде (RunPod) — round-trip, тяжелее; (c) чинить cv2 локально.
- **Рекомендация:** (a) локальный ffmpeg, нарезка каждый N-й / по смене сцены во временную папку.
- **Объём:** M (инфра ffmpeg + util извлечения + tg-intake видео + тесты на фикстуре-клипе). · **Риск:** MED (инфра-зависимость, temp-файлы, лимиты числа/размера кадров для vision). · **Зависимости:** решение по ffmpeg. Блокирует 4/5.

## Этап 4 — Выбор лучшего кадра (Daniil: кадр Grok не идеален)
Гибрид: **FaceValidator (InsightFace, уже есть)** скорит кадры по наличию/размеру/фронтальности лица + резкость (Laplacian) → top-K → Grok выбирает финал среди top-K (или разбивает ничью). Так чиним «кадр Grok не идеален» локальным объективным фильтром.
- **Объём:** M (frame-scoring через FaceValidator + Grok-pick + merge + тесты). · **Риск:** MED («лучший» субъективен, нужна живая итерация с Daniil; FaceValidator-reuse сильно де-рискует). · **Зависимости:** Этап 3 (кадры), Этап 1 (Grok), FaceValidator.

## Этап 5 — Промт, воспроизводящий движение из видео
Послать последовательность кадров/keyframes в Grok с НОВЫМ вопросом «опиши реальное движение между кадрами» (не дефолтное subtle-motion) → результат в `motion_prompt`/`custom_prompts` (слот существует). Refusal-детекция переиспуется. Формат под WaveSpeed/Seedance.
- **Объём:** M (новый Grok-вопрос мульти-кадр + врезка в custom-prompt слот + тесты). · **Риск:** MED (качество описания движения из кадров; формат под движки). · **Зависимости:** Этап 1, Этап 3.

## Этап 6 — Связка свап + анимация (оркестрация + UX)
Лучший кадр → свап (`/swapbatch` SwapEngine); промт движения → анимация (двухдвижковый video-maker). Новый флоу/команда «видео-референс → анимированный свап», стейт-менеджмент, money-safety через НЕСКОЛЬКО платных шагов.
- **Объём:** M–L (оркестрация + UX + state). · **Риск:** MED–HIGH (e2e, деньги на многих шагах, UX — больше всего движущихся частей). · **Зависимости:** 3,4,5 + существующие свап/анимация.

## Рекомендованный ПОРЯДОК
1. **Веха A (быстрая победа):** Этап 0 → 1 → 2. Малый объём, низкий риск, проверяет Grok-интеграцию + uncensored vision на реальной ✨ с контентом Daniil. **Сразу анблокирует исходный провал ✨.**
2. **Веха B:** Этап 3 (решить ffmpeg локально). Анблокирует всё видео.
3. **Веха C:** Этап 4 + 5 (можно частично параллельно).
4. **Веха D:** Этап 6 (полная оркестрация + UX).

**Размер:** XS — Этап 0. S — Этап 1, 2. M — Этап 3, 4, 5. L — Этап 6.

2. **✨-движок:** Grok заменяет Claude или свитч с Claude-fallback? — рекомендую env-свитч, дефолт Grok для motion, Claude как fallback.
3. **Лучший кадр:** ок гибрид Grok + FaceValidator?

## Money-safety (сквозное)
Каждый платный вызов (любой Grok-запрос, свап, анимация) — `check_limit` ДО, `record_cost` ПОСЛЕ успеха; на отказ/None не платим. Admin безлимит, friend под дневным лимитом.
