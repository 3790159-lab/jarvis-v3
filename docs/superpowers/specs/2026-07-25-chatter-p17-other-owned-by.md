# Спека-коротыш: P17 — владелец долга для `kind=other`

**Дата:** 2026-07-25 · **Повод:** живой дрил Д-10 (шаг 2) вернул красное на `obligations_unchanged` · **Объём:** XS–S

## 1. Что сломано (корень точнее, чем в PROBLEMS)

У volska висели два открытых обязательства с `owed_by=bot`, по смыслу — ход КЛИЕНТА: «клієнт ще не оплатив», «клієнт ще не обрав спосіб оплати». Открытый bot-долг рендерится в промпт brain как «відпрацювати ПЕРЕД хендоффом» → бот дожимает лида по тому, что тот должен сделать сам.

Механизм — не «модель назначила бота», а **дефолт в коде**:

```python
# obligations_slot.py:97
owed_by = (upd.get("owed_by") or "bot").strip()
```

Поля `owed_by` в схеме классификатора **нет вообще** (убрано осознанно: для `brief/examples/recalc` владелец — инвариант кода). Значит **любой** `other`, который вернёт модель, молча становится долгом бота. Это не сбой модели, а отсутствующее решение: у свободной корзины `other` владельца не спрашивают, а подставляют.

## 2. Решение

**Вернуть `owed_by` в схему ТОЛЬКО для `kind=other`** (`bot|client`). Жёсткая тройка (`brief/examples/recalc`) поля не получает — там владелец остаётся инвариантом кода (`filter_model_updates` форсит `bot`), `owner_write` — тоже (его жизненный цикл ведёт код).

Клиентский факт помечается `client`, в bot-секцию не попадает: `render_slot_block` уже фильтрует `owed_by == "bot"` — новая точка контроля не нужна, работает существующая. Сами записи — готовое топливо для client-owed слоя (бэклог п.7 §13: «чего ждём от ЛИДА» для реактивации).

### 2.1 Поправка к дизайну: дефолт закрываем, а не оставляем

Добавить поле мало: **пока дефолт `or "bot"` жив, при любом пропуске поля баг возвращается ровно в исходном виде.** Три варианта дефолта для `other`:

| Дефолт | Что происходит при пропуске поля | Цена ошибки |
|---|---|---|
| `bot` (сегодня) | клиентский факт снова в bot-секции | **баг P17 возвращается молча** |
| `client` | реальное обещание бота исчезает из промпта | бот забыл, что обещал — то, против чего строился весь слот |
| **отказ (выбрано)** | `other` без владельца не создаётся, пишется `warning` | теряется свободная заметка — и это ГРОМКО |

Выбран отказ: у свободной корзины владелец обязан быть назван. Цена ошибки минимальна, потому что настоящие обещания бота покрыты каноническими видами (`brief/examples/recalc/owner_write`), у которых владелец задан кодом и не зависит от модели вовсе. Молчаливый дефолт в любую сторону — это ровно тот класс, который и породил P17.

### 2.2 Отвергнутая альтернатива: «вовсе не создавать долг из клиентского факта»

Не берём по двум причинам. Во-первых, она не убирает точку отказа: модель всё равно принимает то же решение, только теперь «промолчать» вместо «пометить `client`» — ошибка просто становится невидимой. Во-вторых, выбрасывается материал, который §13 (client-owed → follow-up) нужен по назначению: «чего ждём от лида» — это и есть основание для реактивации. Хранить с `owed_by=client` дешевле, чем потом собирать заново.

## 3. Что меняется

1. `classifier.py` — `owed_by` в схеме `obligations` с оговоркой «только для other», инструкция + **анти-образец** («клієнт ще не оплатив» → `client`, а не bot-долг). Обе копии промпта (обычная и no-thinking).
2. `obligations_slot.merge_updates` — `other` без явного `owed_by` отбрасывается с `logger.warning`; для остальных видов дефолт `bot` сохраняется (там он и есть инвариант).
3. Сторож: тест, что дефолт `bot` больше не может применяться к `other`.

Ретро-миграция существующих строк НЕ делается: эвристика по тексту детали на трёх языках — хрупкая. Два висящих фантома сняты руками (`scripts/drop_phantom_obligations.py`, идемпотентно, `cancelled` не `DELETE`).

## 4. Приёмка

- **Тест-антипод (главный):** `{kind: other, owed_by: client, detail: "клієнт ще не оплатив"}` → строка создаётся, в `render_slot_block` секции «ВІДКРИТІ ЗОБОВ'ЯЗАННЯ» её НЕТ.
- `{kind: other, owed_by: bot}` → рендерится (свободные обещания бота не потеряны).
- `{kind: other}` без владельца → строка НЕ создаётся, есть warning.
- Канонические виды без `owed_by` → по-прежнему `bot` (инвариант цел).
- Контракт-тест промпта: `owed_by` присутствует в схеме и оговорён как «только для other»; анти-образец на месте.
- Живьём: перезапуск Д-10 — на ходах про оплату у бота не появляется bot-долг с текстом про действие клиента.

⚠️ Правка меняет стабильный префикс промпта классификатора → первый ход после деплоя будет холодным (плата за новый кэш, $0.1191). Для дрила это штатно: его первый ход холодный по договору.
