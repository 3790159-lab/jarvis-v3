# Спека: клиентская панель Ярины отдельным инстансом (для Артёма)

- **Заведено:** 2026-08-18, пункт 3.2 списка владельца.
- **Решение владельца по доступу:** получено в телеграме 18.08 23:47
  (`ask_owner` qid `8706fb694e2c`): **A) Tailscale**. Наружу не торчит ничего.
- **Статус:** ЖДЁТ ОК. Кода нет.

## Задача

Поднять клиентский дашборд (`/panel/tamapi`) на БД Ярины
(`.secrets/yarina.db`), чтобы Артём видел свою панель и не видел ни Ольгу, ни
внутренности фермы.

## Что вскрыл замер — «просто второй инстанс» отдавать НЕЛЬЗЯ

### Ф1. Второй `app.main` = ВТОРОЙ рестартер бота

`app/main.py:308-309` на старте вешает две фоновые задачи, и одна из них —
`_watchdog_loop()`, которая КАЖДЫЕ 60 с зовёт `restart_bot_if_dead()`
(`app/main.py:321-338`). Второй инстанс поднимет второй такой цикл: два
независимых процесса начнут решать, жив ли бот, и поднимать его.

Это ровно тот класс, который 18.08 стоил прода (DEV-38) и 16.08 — 13 ч 42 мин
простоя Ольги: несколько хозяев у одного процесса. Панель не имеет права
приносить с собой второго сторожа бота.

### Ф2. Тот же ключ открывает Артёму панель ДЖАРВИСА

`app/main.py:236-244`: три роутера монтируются ОДНИМ блоком по одному признаку
— задан `JARVIS_PANELS_KEY`. `require_owner` у клиентского дашборда и у
`/panel/jarvis` — **один и тот же ключ**. То есть, выдав Артёму ключ второго
инстанса, мы вместе с его панелью отдаём `/panel/jarvis`: PID'ы, ветки, сроки
ключей, состояние фермы.

Отдельный ключ проблему НЕ решает: он открывает обе панели ЭТОГО инстанса.

### Ф3. Побочная находка, к Ярине отношения не имеет — но чинить надо

`TAMAPI_HEARTBEAT` не задан НИГДЕ (`.env`, `.env.runpod`,
`backend_guardian_detached.ps1` — пусто), значит панель читает дефолт
`state/chatter_heartbeat.txt` (`app/routers/tamapi_dashboard.py:39`). Этот файл
заморожен на **16.08 17:08** — на минуте, когда поднялся мультиклиентный
гардиан (PID 3148, старт 16.08 17:08:30). Живые пульсы с тех пор пишутся
пофайлово: `chatter_heartbeat_volska.txt` (свежий), `chatter_heartbeat_yarina.txt`.

Следствие: `_heartbeat_age()` > 90 с → `_status()` возвращает `down` →
**панель Ольги вторые сутки показывает «Немає зв'язку — технічна проблема»,
пока её бот жив и отвечает.** Это ложь клиенту на проданном экране.

`ops_watchdog.py:125-131` этот раскол уже знает (легаси-имя + glob по клиентам).
Панель и `healthchecks_ping.ps1:40` — не знают.

## Решение

1. **Тонкое приложение вместо `app.main`.** Новый `app/panel_client.py`:
   FastAPI, в котором смонтированы РОВНО `panels_auth` + `tamapi_dashboard` и
   `install_panel_auth_redirect`. Ни `/panel/jarvis`, ни фоновых задач, ни
   сорока роутеров. Закрыто по составу, а не по настройке: то, чего в
   приложении нет, нельзя открыть опечаткой в env.
2. **Свой ключ.** `JARVIS_PANELS_KEY` инстанса Ярины ≠ ключ владельца.
3. **Свои env:** `TAMAPI_DB=.secrets/yarina.db`, `TAMAPI_SLUG=yarina`,
   `TAMAPI_HEARTBEAT=state/chatter_heartbeat_yarina.txt`.
4. **Свой порт** 8011, бинд — тайлнет-адрес (тот же `resolve_bind_host`,
   что у бэкенда), НЕ 0.0.0.0.
5. **Ф3 чинится отдельно и первой** — она бьёт по ЖИВОЙ панели Ольги:
   дефолт `TAMAPI_HEARTBEAT` вывести из `TAMAPI_SLUG`
   (`chatter_heartbeat_{slug}.txt`) с падением на легаси-имя, если файла нет.

## Сторожа (пишет НЕ автор плана)

- тонкое приложение НЕ содержит маршрута `/panel/jarvis` — проверять по
  `app.routes`, а не глазами;
- тонкое приложение не поднимает ни одной фоновой задачи: после старта
  `asyncio.all_tasks()` не содержит `_watchdog_loop`/`_periodic_cleanup`;
- дашборд на `TAMAPI_DB=yarina.db` не отдаёт ни одного диалога Ольги;
- Ф3: при `TAMAPI_SLUG=volska` панель берёт `chatter_heartbeat_volska.txt`, и
  на живом пульсе статус НЕ `down`; сторож обязан краснеть на сегодняшнем
  состоянии дерева.

## Как заходит Артём (решение A)

1. Владелец шлёт приглашение в тайнет из админки Tailscale (действие с
   аккаунта владельца, я его выполнить не могу).
2. Артём ставит клиент, входит по приглашению, получает адрес `100.x`.
3. Ссылка вида `http://<tailnet-host>:8011/panel/tamapi`, ключ — отдельным
   сообщением.
4. Ограничение доступа — ACL тайнета на порт 8011, если владелец захочет
   сузить до одного устройства.

## Что НЕ делаем

- не открываем наружу (вариант B отклонён владельцем);
- не трогаем инстанс Ольги на 8010;
- не заводим Артёму доступ к `/panel/jarvis` ни в каком виде.
