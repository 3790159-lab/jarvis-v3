## Порядок и почему такой

Всё зависит от одного артефакта — `brief.json`. Пока его форма не зафиксирована,
параллелить нечего: три задачи начнут выдумывать разные ключи и сойдутся только
на приёмке. Поэтому **волна 1 — только T1**, и её выход становится контрактом.

Дальше T2/T3/T4 не зависят друг от друга (генератор пишет файлы, отчёт читает
brief.json, проверки читают готовые файлы) — идут параллельно.

## 🔴 Дисциплина сторожей

**Сторожа пишет НЕ автор кода.** На каждую задачу два агента:

- **исполнитель** — получает раздел спеки + контракт данных, пишет код;
- **сторож** — получает ТОЛЬКО раздел спеки (контракт) и список наблюдаемых
  фактов, кода исполнителя НЕ ВИДИТ, пишет тесты от требований.

Оба стартуют одновременно от одного текста. Свожу я: прогоняю сторожей против
кода. Расхождение = находка, а не «поправь тест». Иначе тест и код наследуют
одно неверное допущение, и оба зеленеют на неверном поведении.

Каждая задача закрывается мутацией в ОБЕ стороны: сломать правило → сторож
краснеет; вернуть → зелёный. Без этого сторож не доказан.

## Контракт данных (фиксирую ЗДЕСЬ, чтобы не выдумывали врозь)

### `brief.json` — выход T1, вход T2 и T3

```json
{
  "schema_version": 1,
  "source": "<имя файла брифа>",
  "fields": {
    "q22_price_list": {
      "col": 22,
      "question": "<текст вопроса из строки 0, дословно>",
      "raw": "<значение ячейки как есть, включая мусор>",
      "value": "<нормализованное значение ИЛИ null, если verdict != ok>",
      "verdict": "ok | suspect | garbage",
      "reason": "<null для ok; иначе класс мусор-детектора>",
      "target": "knowledge | playbook | settings | examples | report_only"
    }
  }
}
```

**Инварианты, которые обязан держать сторож T1:**

1. `raw` присутствует ВСЕГДА, даже для `garbage` — детектор ничего не удаляет,
   он понижает поле до «ответа нет». Потеря `raw` = потеря улики.
2. `value` равен `null` при `verdict != ok`. Ровно это правило не даёт мусору
   доехать до конфига.
3. `reason` непуст при `verdict != ok`. «Мусор без причины» неотличим от бага
   детектора.
4. Расхождение схемы и брифа = **rc 2 и карта** (колонка, ожидали, нашли,
   совпадение), а не догадка и не тихий фолбэк.

### `report.json` — выход T3, вход T4

```json
{
  "schema_version": 1,
  "sections": {
    "taken":    [{"field_id": ..., "target_file": ..., "anchor": ..., "quote": ...}],
    "defaulted":[{"key": ..., "value": ..., "why": ..., "brief_wanted_other": bool, "brief_quote": ...}],
    "missing":  [{"field_id": ..., "raw": ..., "verdict": ..., "reason": ..., "stub": ..., "question_for_client": ...}]
  },
  "flags": [{"check": "C12|C13", "file": ..., "line": int, "quote": ..., "question": ...}],
  "counters": {"services": int, "prices": int, "deadlines": int,
               "stop_words": int, "forbidden": int, "example_pairs": int}
}
```

**Инвариант:** пустой блок флагов печатается как «флагов нет». Молчание и
отсутствие проверки обязаны различаться — иначе однажды не отличим «флагов нет»
от «блок не собрался».

## Задачи

### T1 — `form_schema.yaml` + `brief.py` (волна 1, блокирует остальные)

Спека §1. Форма фиксируется как **v1** (решение q4).

- Ведёт позиция колонки, сторожит отпечаток вопроса: casefold, NBSP→пробел,
  снять пунктуацию, ВСЕ апострофы к одному (в брифе живут `U+02BC` и `U+2019`),
  выкинуть стоп-слова; Jaccard ≥ **0.6**.
- Мусор-детектор: шесть классов из §1.2, все взяты из РЕАЛЬНОГО брифа.
- `target` объявлен в схеме, а не выводится из текста. ICP/анти-ICP/ЦА →
  только `playbook`.
- Факт для схемы снят: бриф — один лист «Ответы на форму (1)», **57 колонок**,
  строка 0 — вопросы, колонка 0 — «Отметка времени».

### T2 — `render.py` (волна 2)

Спека §2, правила R1–R9. Самое дорогое место — R1/R2: точка внутри ценовой
строки рвёт фрагмент, и **guardrail режет собственный прайс клиента**.
Замер эталона: 31 ценовое число и 18 срочных.

### T3 — `report.py` (волна 2)

Спека §3. Три раздела + блок ФЛАГИ четвёртым. Главная ценность арки — раздел 3:
готовый текст вопросов клиенту.

### T4 — `checks.py` (волна 2)

Спека §4, C1–C14. C12/C13 — **флаги, а не красное** (rc остаётся 0).
Плюс решение q3: **без файла `REVIEWED` `--check` не зелёный.**

### T5 — `__main__.py` + `--diff` (волна 3)

Коды выхода: `0` зелёное, `1` красное, `2` не состоялось. Выход — в
`build/onboard/<slug>/`, и `build/` дописывается в `.gitignore` (проверено:
сейчас его там НЕТ, бриф содержит имя, контакты и внутренние цены клиента).

### T6 — генератор дрил-сценария (волна 3, решение q1)

Заготовка из пяти ходов: цена → выбор услуги → готовность записаться →
контрольный вопрос из раздела 3 отчёта → просьба скидки. Контрольный шаг
берётся из «Чого ми НЕ знаємо» автоматически.

⚠️ **DEV-32 в силе:** шаг из одних эмодзи в заготовку НЕ ставить, пока судья
дрила его не опознаёт — иначе сгенерированный сценарий обречён краснеть.
