# Д-10 — живой дрил слота обязательств (приёмка арки б)

**Что проверяем живой моделью** (фикстуры не могут): (1) классификатор создаёт/
закрывает обязательства ПО ВЫПОЛНЕНИЮ ФУНКЦИИ, не по слову; (2) owner_write ведёт
КОД по факту карточки; (3) §8-дамп показывает собранный промпт с обеими секциями;
(4) дельта стоимости ≤ +10%. Критерии 3 (переживание окна) и 9 (анти-повтор) уже
доказаны фикстурами (`test_obligations_wiring.py`) — здесь не дублируем.

Прогон на semidemo волски, контакт = твой id. **funnel_gate НЕ трогать.**

## Включение (перед дрилом)
В окружении раннера (launch-env гардиана), затем рестарт раннера:
```
CHATTER_OBLIGATIONS_SLOT=1     # включить арку (default off)
CHATTER_PROMPT_DUMP=1          # полный дамп промпта на время приёмки → logs/prompt_dump.log
```
`_obligations_enabled()` читает env НА КАЖДЫЙ ход; но env процесса фиксируется при
старте → нужен рестарт раннера, чтобы флаги вступили. Зафиксируй epoch включения
(`ts_flip`) — по нему считается дельта.

**Сначала 3–4 хода С ВЫКЛЮЧЕННЫМ слотом** (baseline стоимости), потом включить и
повторить эквивалентные ходы.

## Ходы и ожидаемое поведение

| Ход | Реплика лида | Ожидание бота | Слот (проверка по dump / DB) |
|---|---|---|---|
| T1 | «Привіт, цікавить ребрендинг лого» | по сути + уточнение/пропозиція брифу | если пообещала бриф → `brief` **open** создан |
| T2 | «а що вам треба від мене для старту?» | задаёт квал-вопросы (символ/текст, референси, стиль) = **выполняет** бриф | `brief` → **delivered** (по функции, а не по слову «бриф»); в блоке появляется секция «ЗАКРИТО НЕДАВНО: бриф ✓» |
| T3 | «все зрозуміло, давайте почнемо, як оплатити?» | тригер 2 → передача керівниці + карточка владельцу | классификатор мог создать `owner_write` **open**; карточка доставлена → **КОД** ставит `owner_write` **delivered** с `closed_msg_id` = id карточки. Если классификатор прислал owner_write delivered/cancelled — **проигнорировано** |
| T4 | «ще подумаю» | по сути, без повторного навязывания брифа | `brief` в «ЗАКРИТО НЕДАВНО» → бот НЕ переспрашивает уже отданное |

## Как читать §8-дамп
`logs/prompt_dump.log` — блоки `===== tag=brain … =====` + полный system. На T2+
внутри suffix виден:
```
=== ВІДКРИТІ ЗОБОВ'ЯЗАННЯ (відпрацювати ПЕРЕД хендоффом) ===
- brief: …            (пока open)
=== ЗАКРИТО НЕДАВНО (НЕ повторювати) ===
- brief ✓ — …         (после delivered)
```
Структурная строка (всегда, PII-free) в логе раннера: `prompt-shape tag=brain
sys_chars=… suffix_chars=… sha=… obl=n=… status=… open=[…] delivered=[…]`.

## Дельта стоимости (гейт ≤ +10%)
```
python scripts/obligations_cost_delta.py --db .secrets/demo.db --split-ts <ts_flip>
```
Печатает $/ход ДО (baseline, слот off) и ПОСЛЕ (on) + дельту %. Если трещит по
+10% — первым режем окно «ЗАКРИТО НЕДАВНО» 7→3 дня (`RECENT_DAYS` в
`obligations_slot.py`), механику не трогаем; повторный замер.

### Два правила окна замера (иначе цифра врёт)

Наивный замер на данных Д-10 напечатал **+15.3% (гейт «превышен»)** там, где
сопоставимый даёт **+2.1%**. Оба искажения теперь в дефолтах скрипта:

1. **Окно = ТЕКУЩИЙ ДЕНЬ.** `--since` по умолчанию = сегодня 00:00. Ходы прошлых
   дней шли на другом промпте/персоне (sys рос от правок playbook) и baseline'ом
   быть не могут: на истории с 07-23 дельта показывала +32.8% при неизменной
   механике слота. Полная история — только явным `--since 0`, и это **тренд, а не
   гейт**. ⚠️ Если дрил перевалил за полночь — передавай `--since` дня дрила
   явно (epoch 00:00 того дня), иначе окно окажется пустым.
2. **Cold-start ходы исключаются** из обеих сторон. Ход на ХОЛОДНОМ кэше платит
   `cache_creation` вместо `cache_read` (brain **$0.040** вместо **$0.011**, ×3.6).
   На Д-10 один такой ход (T4 в 22:36) из восьми задирал ON-среднее на ~13%.
   Признак — `cache_creation_input_tokens > 0` **на brain-вызове**; у
   классификатора `cache_read=0` ВСЕГДА (он кэш не читает вообще) — это не признак
   холода. Сколько ходов отброшено, печатается всегда; `--include-cold` возвращает
   старое поведение.

   ⚠️ **Поправка 2026-07-25:** холодный кэш = истёкший TTL (разрыв > 1ч), а НЕ
   рестарт раннера. Кэш живёт на стороне API и переживает перезапуск процесса —
   проверено фактом: раннер рестартовал в 01:16, brain в 01:17 прочитал кэш
   (`cr=8801`) через 38 минут после предыдущего хода. У T4 холод был от разрыва
   3.5 часа (19:03 → 22:36), рестарт в 21:52 к нему отношения не имел.

Фактические числа приёмки Д-10 (`--split-ts 1784903580 --since 1784840400`):
```
OFF (baseline, до split):   4 ходов  $0.0503/ход
ON  (слот включён):         7 ходов  $0.0513/ход
исключено cold-start ходов: OFF 3, ON 1
ДЕЛЬТА: +2.1%   гейт ≤ +10%   OK
```
Тесты правил окна: `tests/test_obligations_cost_delta_script.py` (9).

**Побочная находка замера (вне арки):** ~78% стоимости хода — это классификатор,
у которого `cache_read=0` на каждом ходу (пишет 7–7.8К токенов в cache_creation =
~$0.029/ход, при brain на тёплом кэше ~$0.011). Кэш классификатора не переиспользуется
вообще. Это отдельная арка экономики, не хвост слота.

## Выключение (после приёмки)
Убрать `CHATTER_PROMPT_DUMP` из `scripts/chatter_guardian_detached.ps1` + рестарт
**таска гардиана** (env раннера фиксируется на старте и наследуется от гардиана:
`Stop-ScheduledTask` → удалить `state\locks\chatter_guardian.pid` → `Start-ScheduledTask`).
⚠️ Свежий гардиан НЕ перезапускает живой раннер (видит heartbeat → «runner alive»):
старый процесс доживает со СТАРЫМ env. Нужен скоупленный kill раннера по PID
(cmdline `*C:\jarvis*chatter.telethon_run*`, `/T`) — гардиан поднимет новый через
~90с (debounce 3×30с) уже с новым окружением. Затем **удалить `logs/prompt_dump.log`**
(ПДн; на приёмке набежало 263КБ за 8 ходов).
`CHATTER_OBLIGATIONS_SLOT=1` — остаётся в гардиан-скрипте как прод-состояние
(строка = рубильник отката).

| $ | +2.1% при гейте ≤ +10% |
| classifier_error | 0 за сутки дрила |

**Три находки, которые не ловились фикстурами** (все три — «зелёный счётчик при
нерабочем поведении», ровно тот класс, ради которого дрил и делался):
1. `owed_by=client` от модели → `renderable=0` при `n=1`: обязательство посчитано,
   но в brain не инъектится. Фикс: `CODE_BOT_OWNED_KINDS` + `owed_by` убран из
   схемы классификатора + §8-строка разделена `n=`/`renderable=`.
2. `brief` не закрывался по функции («жду материалов от клиента») + плодилось
   дублирующее `other` про тот же долг. Фикс: явный критерий+анти-пример в
   промпте, детерминированный бэкстоп в `merge`.
3. `owner_write` тихо **переоткрывался**: пока платёжный контекст в окне истории,
   классификатор эмитил `open` каждый ход → сбрасывался `closed_msg_id` → на
   следующем ходу ложная повторная передача керівниці. Фикс: `filter_model_updates`
   existing-aware; жизненный цикл после создания ведёт только код.
