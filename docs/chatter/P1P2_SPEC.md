# P1P2_SPEC: шифрование секретов at rest (двухслойный вариант, ревизия 2)

**Дата:** 2026-07-22 (рев. 2 после ребут-теста №2) · **Спринт 0, пункт 1** · **Статус:** дизайн пересобран (§0), **ждёт ОК Даниила на ревизию**. Cutover живых секретов — отдельный повторный ОК. Код — ветка `sprint0/secrets-p1p2`.

**Критерий приёмки (проверяемый, рев. 2):**
1. **Бут без интерактивного логона → гардиан поднял раннер и расшифровал секреты** (heartbeat + лог без ошибок decrypt).
2. **Том зашифрован, украденный диск не даёт доступа** (`manage-bde -status`: Protection On, TPM-протектор, clear-key протектора нет).

ACL защитой **не считается** — на украденном носителе не действует.

---

## 0. Ревизия 2026-07-22: почему пересобрано

**Ребут-тест №2 — FAIL premise:** зелёный user-scope DPAPI на AtStartup-старте объяснялся автологоном (ARSO); в честном окне «до логона» user-scope недоступен. ARSO восстановлен, проба `DpapiBootProbe_TEMP` удалена (§13).

**Развилка признана:** безлюдный старт после блэкаута и стойкость к краже диска **несовместимы в рамках одного DPAPI**. Machine-scope + entropy на том же диске критерий «украли диск → нет takeover» НЕ выполняет: вор получает и блоб, и entropy-файл, и системные хранилища для офлайн-восстановления machine-ключа; ACL на украденном носителе не действует.

**Решение — два слоя, каждый закрывает свою угрозу:**
- **Слой «диск» (§0.2):** шифрование тома BitLocker с ключом в TPM → безлюдный старт сохраняется, украденный диск/бэкап бесполезен. Покрывает заодно `.env`, БД лидов, бэкапы на E:.
- **Слой «процесс» (§0.3):** machine-scope DPAPI + optionalEntropy (32Б) + жёсткий ACL → защита от других пользователей и непривилегированных процессов на живой машине.

### 0.1 Факты по машине (сняты 2026-07-22)

| Факт | Значение |
|---|---|
| TPM | **Есть: 2.0** (Intel PTT, INTC, ManagedAuthLevel Full). Present/Ready/Enabled/Activated/Owned = True. Lockout чист (0/31). ⚠️ `RestartPending=True` — перед включением протекторов нужен ребут. |
| Secure Boot | **Включён** → PCR7-биндинг доступен → **TPM-only unlock возможен** (без PIN, безлюдный старт сохраняется). |
| BitLocker C: (OS, 110ГБ) | 100% encrypted, XTS-AES-128, Used Space Only, **но Protection Off, Key Protectors: None Found** |
| BitLocker D: (1.9ТБ), E: (JarvisData, 954ГБ) | То же: 100% encrypted, **Protection Off, протекторов нет**, auto-unlock disabled |
| Автологон (classic) | НЕТ: `AutoAdminLogon` пуст, `DefaultPassword` не задан |
| ARSO | Активен (policy не задана = дефолт). Восстановлен после теста №2. |

**Ключевой вывод:** тома *формально* зашифрованы, но `Protection Off` + нет протекторов = **clear key**: VMK лежит на томе открыто, сейчас шифрование от кражи диска НЕ защищает вообще. Хорошая новость: включение защиты = добавить протекторы + enable, **повторное шифрование не нужно** (минуты, не часы). Железо позволяет закрыть «кражу диска» шифрованием тома — альтернативы §0.4 не нужны.

### 0.2 Слой «диск» — BitLocker TPM-only (закрывает кражу носителя)

Порядок (документирую, НЕ выполняю без ОК; всё делается после ребута из-за `RestartPending`):

1. **C: (OS):** `manage-bde -protectors -add C: -TPM -RecoveryPassword` → recovery password (48 цифр) **сохранить вне машины ДО следующего шага** → `manage-bde -protectors -enable C:`. Проверка биндинга: `manage-bde -protectors -get C:` (ожидаем PCR 7,11 при Secure Boot).
2. **D:, E::** `manage-bde -protectors -add <X>: -RecoveryPassword` → `manage-bde -autounlock -enable <X>:` → `manage-bde -protectors -enable <X>:`. External key auto-unlock хранится на зашифрованном C: — тома открываются автоматически после C:, безлюдность сохраняется.
3. **Recovery-ключи всех трёх томов — вне машины**, рядом с §12-бэкапом. Без них смерть TPM/материнки = потеря всех томов разом. **Без сохранённых ключей защиту не включать.**
4. Проверочный ребут: машина поднимается сама (TPM-only), `manage-bde -status` = Protection On везде.

Что слой закрывает: кража/копия диска, бэкапа, любого файла с тома в выключенном состоянии — включая `.env`, БД лидов, plaintext-хвосты, бэкапы на E:.

**Что слой НЕ закрывает (честно):**
- **Кража машины целиком** (диск + TPM): том расшифруется при буте, защита сводится к Windows-логону. Требования: стойкий пароль учётки, классический автологон не заводить никогда (факт §0.1: его нет). ARSO после ребута логинит и лочит экран — приемлемо.
- **Живая/спящая машина:** DMA/cold-boot-атаки — вне модели угроз (опционально: запретить S3 sleep).
- **Used Space Only:** сектора, освобождённые ДО первичного шифрования, могли остаться plaintext. Опциональное добивание: `manage-bde -w C:` (wipe free space) — актуально для C:, где жили plaintext-секреты.
- **TPM-only слабее TPM+PIN** (атаки класса sniffing шины/bootkit до логона), но PIN = конец безлюдного старта. Осознанный выбор в пользу безлюдности.

### 0.3 Слой «процесс» — machine-scope DPAPI + entropy + ACL (живая машина)

- `CryptProtectData` scope=LocalMachine + **optionalEntropy = 32 случайных байта** (`os.urandom`), файл `.secrets/entropy.bin`.
- **ACL** на `.secrets\` (включая `entropy.bin`, `*.enc`) и `.env.enc`: только **SYSTEM + Administrators**, наследование срезано (`icacls /inheritance:r`). Раннер/гардианы бегут под `PC-LOE\Admin` (member of Administrators) → читают.
- Что даёт: процесс другого пользователя / непривилегированный процесс на живой машине machine-блоб без entropy не расшифрует, а entropy закрыта ACL.
- Machine-scope **не зависит от логона и пароля юзера** → AtStartup-старт до первого логона гарантирован архитектурно (не держится на ARSO/автологоне); оговорка §9.1(б) о смене пароля снимается.
- **Остаточный риск — без приукрашивания:** компрометация локального админа / код под Admin или SYSTEM на живой машине = полный доступ к секретам (читает entropy, зовёт DPAPI). **Это цена безлюдного старта.** ACL — не криптография: на живой машине это граница «другие пользователи и непривилегированный код», не больше.

### 0.4 Fallback-альтернативы (НЕ нужны — TPM есть; фиксирую на случай отказа железа)

| Вариант | Цена |
|---|---|
| (а) Password protector тома без TPM | Кража диска закрыта, но **потеря безлюдности**: каждый блэкаут = ручной ввод пароля на буте |
| (б) Внешний источник ключа (USB startup key / Network Unlock) | Безлюдность условная (ключ-носитель воткнут рядом = украден вместе с машиной; Network Unlock = +инфраструктура WDS/DHCP) |

**Рекомендация:** TPM-only (основной путь). Альтернативы не внедрять.

## 2. Дизайн

### 2.1 Мастер-слой — DPAPI machine-scope + entropy (рев. 2, было user-scope)

`CryptProtectData` с флагом `CRYPTPROTECT_LOCAL_MACHINE` + optionalEntropy из `.secrets/entropy.bin` (§0.3). Блоб расшифровывается только на этой машине процессом, способным прочитать entropy-файл. Интерактивный ввод не нужен; от логона/пароля юзера не зависит → старт AtStartup до первого логона работает (в отличие от user-scope — §13). Защита от копии диска — **не здесь**, а в слое «диск» (§0.2).

- Реализация: `ctypes` к `crypt32.dll` (уже сделано в `crypto.py`, user-scope) → правка: флаг scope + параметр entropy. Живых секретов в `.enc` ещё нет (cutover не было) — перешифровка дёшева, тестовые блобы пересоздать.
- Требование к принципалу смягчается: не «тот же пользователь», а «член Administrators» (ACL на entropy). Факт: гардианы/раннер под `PC-LOE\Admin` (§9-Р O3) — проходит.

### 2.2 Session — через StringSession, БЕЗ plaintext-файла на диске
Ключевое решение: **не** держать расшифрованный `.session` файл на диске даже временно. Вместо файловой сессии:
1. Экспортировать текущую сессию в **StringSession** (Telethon умеет: `StringSession.save(client.session)`).
2. Зашифровать строку DPAPI → хранить `.secrets/<slug>.session.enc` (шифртекст).
3. Раннер на старте: читает `.enc` → DPAPI-decrypt в память → `TelegramClient(StringSession(s), api_id, api_hash)`. **Plaintext-сессии на диске нет никогда.**

Это чище файлового варианта (где decrypt-в-temp оставляет окно plaintext). Точка правки — `derive_session_path`/создание клиента в `telethon_run.py` + `telethon_login.py` (при логине сразу сохранять `.enc`, не `.session`).

### 2.3 `.env` — decrypt-в-память при загрузке + ACL
- Хранить `.env.enc` (DPAPI-шифртекст всего файла). Маленький загрузчик: читает `.enc` → decrypt в память → парсит в `os.environ` (замена `dotenv.load_dotenv`). Plaintext `.env` на диске не лежит.
- ⚠️ `.env` читают **многие** процессы Jarvis, не только chatter — объём миграции решён в §9-Р O1 (всё, но поэтапно).
- ACL (icacls): снять чтение у всех, кроме SYSTEM+Administrators — независимо от шифрования, как defense-in-depth.
- Рев. 2: до перехода консьюмера на загрузчик его plaintext `.env` дополнительно прикрыт слоем «диск» (украденный носитель не отдаёт и plaintext).

### 2.4 БД (переписка лидов, P8/S5)
В минимальный вариант шифрование БД **не** входит (Даниил: «шифрование session+`.env`»). Решение §9-Р O2: ACL сейчас + шифрование бэкапов сейчас; полное шифрование БД — к vault. Рев. 2: БД на зашифрованном томе → offline-кража закрыта слоем «диск».

## 4. TDD-план (пишется ПЕРВЫМ, на фикстурах, без живых секретов)

1. `crypto.py`: round-trip (encrypt→decrypt = исходник); decrypt чужого блоба падает явно (не тихо); tamper (битый байт) → ошибка, не мусор.
2. `secret_loader.py`: `.env.enc` → корректный `os.environ`; отсутствие файла → понятная ошибка; StringSession round-trip (сохранить→зашифровать→загрузить→та же строка).
3. Раннер-загрузка: подменный `.enc` с фейковой StringSession → клиент конструируется из строки, не из файла (мокнутый TelegramClient).
4. Негатив: нет `.enc` и нет legacy `.session` → явная ошибка старта, не тихий фейл.
5. Совместимость: legacy plaintext `.session` есть, `.enc` нет → одноразовая миграция (зашифровать, оставить бэкап) — тест миграции.
6. **Рев. 2, entropy:** отсутствие `entropy.bin` → явная ошибка (не тихий fallback на без-entropy); блоб, шифрованный с другой entropy → ошибка decrypt, не мусор; генерация entropy = ровно 32Б из os.urandom, повторный вызов НЕ перезаписывает существующий файл.

Всё это тестируется фикстурами (фейковые строки, tmp-пути); DPAPI-часть — за тонкой обёрткой, в тестах мокается или гоняется на временных данных, НЕ на живом demo.session.

## 6. Cutover — безопасный перевод живых секретов (после ОК Даниила, рев. 2)

Порядок, каждый шаг обратим:
0. **Слой «диск» СНАЧАЛА** (§0.2): ребут (снять TPM RestartPending) → recovery-ключи трёх томов вне машины → протекторы C:, потом D:/E: + auto-unlock → проверочный ребут, Protection On везде. Отдельное окно, ДО секретного cutover — если что-то с TPM пойдёт не так, секреты ещё в старой схеме.
1. **Проверка принципала.** Гардиан/раннер-таски — под членом Administrators (сейчас `PC-LOE\Admin`, O3) — иначе entropy за ACL недоступна.
2. **Бэкап.** Скопировать `demo.session` + `.env` в защищённое место (вне репо, tighter ACL) — страховка отката.
3. **Мердж кода** Спринта 0 в phase-4.0, но раннер пока на старом (не деплоить).
4. **Entropy:** сгенерировать `.secrets/entropy.bin` (32Б) + сразу ACL на него. Entropy включить в §12-экспорт.
5. **Миграция сессии:** оффлайн-скрипт читает `demo.session` → StringSession → DPAPI(machine+entropy) → `demo.session.enc`. Проверить обратную расшифровку в ту же строку.
6. **Миграция `.env`:** `.env` → `.env.enc` (объём по O1).
7. **Maintenance-окно:** остановить гардиан (`-Revert`/disable), деплой нового кода (checkout), старт. Раннер поднимается из `.enc`.
8. **Верификация:** heartbeat идёт; бот отвечает на тестовую реплику (allowlist, гейт закрыт); лог без ошибок расшифровки. Плюс приёмочный ребут-тест §8.1.
9. **Шред plaintext:** только после успешной верификации — удалить plaintext `demo.session` и `.env` (бэкап из п.2 держать до полной уверенности, потом тоже убрать).
10. **ACL** на `.secrets/` и `.env.enc` (финальная проверка `icacls`).

**Гейт при cutover не трогаем** — тестовая реплика идёт с allowlist-id при закрытом гейте.

## 7. Откат

- Любой шаг до п.9 — вернуть бэкап-файлы (п.2), `-Revert` гардиана на старый код (phase-4.0 без шифрования). Раннер поднимется на plaintext как сейчас.
- После п.9 (plaintext удалён) — восстановить из бэкапа п.2. Поэтому бэкап держим до финальной уверенности.
- Слой «диск» откатывается независимо: `manage-bde -protectors -disable C:` (вернуться к clear key) — но это возврат к «шифрование не защищает», только как аварийная мера.
- Риск №1 (рев. 2): раннер без прав на `entropy.bin` → decrypt падает → бот не логинится. Ловится на п.1 и п.8; откат — бэкап.
- Риск №2: TPM-глюк после включения протекторов → том просит recovery key на буте → вводим сохранённый ключ (п.0), разбираемся; безлюдность временно теряется, данные — нет.

## 8. Проверка критерия приёмки (рев. 2 — проверяемые тесты)

### 8.1 «Бут без интерактивного логона → гардиан поднял раннер и расшифровал секреты»
Согласованный ребут → **не трогать клавиатуру** → факт: heartbeat раннера идёт, лог без ошибок decrypt, секреты открыты из `.enc`. Machine-scope не зависит от user-логона, поэтому ARSO тест не мусорит (в отличие от теста №2 user-scope) — но для чистоты фиксируем в протоколе время бута и время первого успешного decrypt из лога.

### 8.2 «Том зашифрован, украденный диск не даёт доступа»
- `manage-bde -status`: все тома Protection On; C: — протектор TPM (+RecoveryPassword), clear-key протектора нет; D:/E: — auto-unlock + RecoveryPassword.
- `manage-bde -protectors -get C:`: PCR-биндинг присутствует (PCR 7,11).
- Опционально (полный физический тест): диск на другой машине → том залочен, требует 48-значный recovery key.

### 8.3 Слой «процесс»
Копия `demo.session.enc` + `entropy.bin` на другую машину → DPAPI отказывает (machine-ключ другой). На этой машине из-под не-админского пользователя → entropy не читается (ACL), decrypt невозможен. Гоняем на копиях, не на живом.
