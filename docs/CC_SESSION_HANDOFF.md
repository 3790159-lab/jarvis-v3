# CC Session Handoff — протокол

Часть DEV-1 («Живучесть CC-сессий», см. CLAUDE.md). Персистентный терминал
(`scripts/start_cc.ps1`, WSL+tmux) решает проблему обрыва SSH/RDP; этот
документ решает вторую половину задачи — обрыв самой CC-сессии (лимит
контекста, краш, ручной restart) без потери прогресса по длинной задаче.

## Где живёт снимок состояния

`state/cc_session_context.md` — живое, не коммитится (`state/` в
`.gitignore`). Это снимок, а не журнал: каждая перезапись полностью
заменяет предыдущую, история не хранится.

Шаблон полей — `docs/cc_session_context.template.md`. Скопировать его в
`state/cc_session_context.md` и заполнить каждую секцию; пустых секций не
оставлять — писать "-" или "нет", если реально нечего сообщить.

Обязательные поля шаблона:
- **Обновлено** — ISO timestamp последней записи
- **Арка** — какой этап docs/MASTER-PLAN.md (или какая задача) в работе
- **Сделано** — список конкретных завершённых шагов, последний сверху
- **Ждёт** — на чём сессия сейчас застряла или что делает следующим
- **Открытые confirm** — подтверждения, показанные Daniil, но ещё не
  подтверждённые тапом
- **iteration_counter** — по одной строке на каждую «ручку»
  (проблему/фичу/баг), которая сейчас итерируется

## Протокол записи

CC перезаписывает `state/cc_session_context.md` в конце **каждого крупного
шага** долгой сессии (не после каждого файла — после смыслового шага:
завершённая подзадача, пройденный/проваленный тест-гейт, эскалация
Daniil). Незаписанный прогресс между шагами — ожидаемый и допустимый риск;
не пытаться писать файл после каждой команды.

## Протокол чтения

**Новая сессия ОБЯЗАНА первым делом при старте проверить, существует ли
`state/cc_session_context.md`.** Если да — прочитать его и продолжить с
зафиксированного состояния (арка, сделано, ждёт, открытые confirm,
iteration_counter), а не начинать с нуля и не повторять уже пройденные
шаги. Если файла нет — обычный старт с чистого листа.

## Стоп-лимит («диминишинг»)

Если **2 итерации подряд** по одной и той же «ручке» (проблеме/фиче/багу,
см. `iteration_counter` в шаблоне) не проходят приёмку — CC ОБЯЗАН
остановиться и эскалировать Daniil явным выбором:
«диминишинг: принять / чинить уровнем ниже / отложить». Третью попытку
молча не предпринимать. Счётчик ручки сбрасывается в 0 только после того,
как она прошла приёмку.

## Живучесть тестов

Любой тест, реально поднимающий WSL/tmux (для проверки `scripts/start_cc.ps1`),
помечать `pytest.mark.integration` + `skipif` по опциональной
env-переменной (см. `tests/test_start_cc_ps1_integration.py`) — в
sanitized-окружении гейта такой тест обязан SKIP, не FAIL. Приёмка
живучести терминала и session-handoff — ручная (Daniil): kill SSH во время
долгого таска → reconnect → сессия жива; новая сессия по «продолжай»
возобновляет контекст из файла.
