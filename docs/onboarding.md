# Онбординг нового клиента chatter

Путь запуска «с нуля до Аня отвечает лидам». **Цель: ~20 минут, без разработчика.**

Прогнан целиком на демо дважды: 2026-07-19 до починки (~1 час, 7 ручных правок
файлов) и после (0 ручных правок конфига). Каждый шаг ниже реально исполнялся.

> Ветка `chatter-onboarding`. До мержа проверь раздел «Что менялось в проде».

---

## 0. Что собрать с клиента ДО начала (5 минут разговора)

| Нужно | Куда пойдёт |
|---|---|
| Номер телефона + доступ к TG-коду | Telethon-логин (шаг 3) |
| 2FA-пароль аккаунта, если стоит | Telethon-логин |
| Имя персоны, возраст, роль | `--persona-name --age --role` |
| Имя владельца + как к нему обращаться | `--owner-id --owner-ref` |
| Прайс/услуги/условия | `/knowledge` (шаг 5) |
| Валюта | `--currency` |
| Свой тестовый TG id | `--allowlist` |
| Ниша (насколько обещания = обязательства) | `strict_knowledge` (шаг 6a) |

### Два варианта аккаунта

- **(а) Номер клиента.** Клиент отдаёт свой TG-аккаунт под воронку.
- **(б) Наш eSIM.** Мы курируем аккаунт целиком.

> **Код идентичен.** Разница ровно одна: на шаге 3 Telethon спрашивает номер и
> код — в (а) их вводит клиент (или диктует по видеосвязи), в (б) мы сами.
> Ни строки конфига, ни строки кода это не меняет.

⚠️ **Оба варианта требуют ВЫДЕЛЕННЫЙ аккаунт, не личный.** На шаге 7 включается
`funnel_gate`: Аня начинает отвечать незнакомцам, а знакомым отвечать перестаёт.
На личном аккаунте это значит, что бот заговорит с реальными знакомыми владельца
от его имени. В варианте (а) проговорить с клиентом под запись. Команда
`/funnel_gate on` теперь сама предупредит и потребует подтверждения — но
подтверждает человек, а не программа.

## 1. Создать клиента — одна команда (1 мин)

```bash
python -m chatter.create_client acme \
  --persona-name Аня --owner-id Дмитрий \
  --age 26 --role "менеджер фотостудии" \
  --currency грн --allowlist 237616472
```

Создаёт `chatter/clients/acme/` с 4 файлами и печатает следующий шаг.
Существующего клиента **никогда не перезаписывает**.

Конфиг минимальный: обязательны только `model`, `language`, `owner_id`,
`persona_name`. `timings` / `limits` / `work_hours` не пишутся вовсе — у них
боевые дефолты. Пропуск поля больше не роняет клиента; **опечатка** в имени
поля — по-прежнему громкая ошибка с перечислением известных ключей.

`pairing_code` (`acme-onboard-01`) и `funnel_gate: false` проставлены сразу.

## 2. Подключить к раннеру (1 мин)

Добавить строку в `chatter/clients/active.yaml`:

```yaml
clients:
  - demo
  - acme          # ← новый
```

**Первый в списке — первичный:** он даёт allowlist, язык пульта и определяет
пути `.secrets/<slug>.session` / `.secrets/<slug>.db`.

Скрипт гардиана править **не нужно** — он читает этот файл.
Разовое переопределение: `--personas acme` или `CHATTER_PERSONAS=acme`.

## 3. Telethon-логин — единственная точка расхождения (а)/(б) (10 мин)

Предусловие: `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` в корневом `.env`
(получить на https://my.telegram.org/apps).

```bash
TELETHON_SESSION=.secrets/acme.session python -m chatter.telethon_login
```

Telethon спросит: **номер телефона → код из Telegram → 2FA-пароль**.
В (а) вводит клиент, в (б) мы. Скрипт печатает, под кем залогинился —
**сверить, что это тот аккаунт**.

Путь сессии совпадает с тем, что раннер выведет из slug'а сам, — задавать
`TELETHON_SESSION` здесь нужно только потому, что логин выполняется отдельным
процессом до первого запуска раннера.

⚠️ `.session` = ПОЛНЫЙ доступ к аккаунту. Уже в `.gitignore` (`/.secrets/`),
никогда не коммитить. В варианте (а) это чувствительный актив клиента —
проговорить, как хранится и как отзывается (`terminate session` в TG клиентом).

## 4. Контрол-бот (3 мин)

1. BotFather → `/newbot` → токен.
2. Токен в `.env` **через секрет-канал** (DEV-2 — значения секретов вводит
   владелец сам, не CC):
   ```
   scripts\add_secret.ps1 -KeyName CHATTER_CONTROL_BOT_TOKEN
   ```
   В `settings.yaml` лежит **имя переменной, не токен** — файл коммитится.

## 5. Запуск + заливка базы (3 мин)

```bash
python -m chatter.telethon_run --personas acme --llm real
```
(под гардианом — просто перезапустить: состав он возьмёт из `active.yaml`)

Затем в пульте:

```
/knowledge ## Услуги
- Портретная фотосессия — 4000 грн, 2 часа, 30 обработанных кадров
- Свадебная съёмка — от 25000 грн

## Условия
- Предоплата 30%
- Готовые кадры за 7 рабочих дней
```

→ `✅ База знаний обновлена (273 симв.) и перечитана.`

Пишет файл, перечитывает конфиг и подтверждает одной командой. Отдельный
`/reload` не нужен. Сломанную запись **откатывает сам**.

**Формат важен:** `/config` считает `##` разделы и `- ` пункты.

## 6. Приёмка: `/config` + живая проверка (3 мин)

```
/config → ⚙️ Настройки
          Персона: Аня, 26 лет
          Язык: ru · Модель: claude-haiku-4-5
          База знаний: 2 разделов, 6 пунктов
          Валюта: грн · запрещённых терминов: 7
          База знаний: строго (отвечаю только из базы, обещания вне её — владельцу)
          Честность: на «ты бот?» отвечаю честно и предлагаю тебя
          Гейт воронки: выкл (отвечаю только allowlist)
          Списки: allowlist 1, denylist 0
```

Сверить построчно с обещанным клиенту. Затем написать Ане с тестового аккаунта:

1. Вопрос по прайсу → отвечает **из knowledge.md**, не выдумывая.
2. **«А ты бот?»** → обязана расколоться честно:
   > `Меня зовут Аня, мне 26. Я менеджер фотостудии — честно говоря, я —
   > виртуальный ассистент, а не живой человек. … подключу владельца — Дмитрий
   > ответит лично.`
3. Вопрос про оплату → ничего из `forbidden_terms` не всплывает.

## 6a. Два тумблера под нишу клиента (settings.yaml)

Оба живут в клиентском `settings.yaml`, у обоих **безопасный дефолт**, и оба
видны в `/config`. Менять — правкой файла + `/reload` (командой пульта не
переключаются намеренно: это не операция «на бегу с телефона»).

### `strict_knowledge` — насколько Аня привязана к базе

| Значение | Поведение | Кому |
|---|---|---|
| `true` (дефолт) | Говорит **только из `knowledge.md`**. Обещание вне базы (скидка, гарантия, рассрочка, «перезвоню», «свяжусь») **подавляется**: лид получает нейтральное «уточню и вернусь», владелец — карточку. | Юр-услуги, медицина, всё, где обещание = обязательство |
| `false` | Отвечает шире, обещание **доходит до лида**. Карточка владельцу приходит всё равно. | SMM, консалтинг, ниши, где сухость убивает диалог |

```yaml
strict_knowledge: false
```

⚠️ **Что НЕ меняется ни в одном режиме:**

- выдуманные **цены и сроки** (`unbacked_claim`) — подавляются всегда;
- `forbidden_terms` (рубли/росбанк/платёжки) — подавляются всегда.

Свободный режим смягчает обязательства, а не даёт право врать про цифры и
оплату. Если Аня в свободном режиме пишет «сделаю скидку 700 грн», ответ всё
равно будет заменён — из-за **цифры**, не из-за обещания.

### `honesty_mode` — раскрывается ли Аня на «ты бот?»

| Значение | Поведение |
|---|---|
| `honest` (дефолт) | На прямой вопрос отвечает честно, что она виртуальный ассистент, и предлагает владельца. |
| `free_owner_liability` | Гарантия снята: ответ пишет модель по персоне, раскрытие не подставляется. **Это не режим сокрытия** — см. ниже. |

```yaml
honesty_mode: free_owner_liability
```

🔴 **`free_owner_liability` снимает гарантию, но НЕ обещает сокрытия.**

Тумблер убирает наш захардкоженный ответ-раскрытие — и только. Он **не** учит
ассистента отрицать, что он бот, и такой функции в продукте нет: полное
сокрытие **не гарантируется и не является целью**. Модель на прямой вопрос
вполне может признаться сама, по собственной персоне.

Это не гипотеза, а наблюдение: живой прогон `volska` 2026-07-21 — честность
выключена в 03:50:10, после чего на «Ви бот?» ассистент всё равно ответил
«Так, я віртуальний асистент» (03:50:43) и «Так, я бот-асистент цієї агенції»
(03:54:17). Код отработал верно; неправильной была наша же строка пульта,
обещавшая «на «ты бот?» НЕ раскрываюсь» — она исправлена.

Практический вывод для продажи: **не продавайте free-режим как «бот сойдёт за
живого человека»**. Обещать это мы не можем, и клиент, купивший такое ожидание,
получит рекламацию на первом же прямом вопросе.

⚠️ **Прежде чем это включать:**

- Значение намеренно длинное — короткое `honesty_mode: free` **отклоняется с
  ошибкой**, чтобы честность не отключилась опечаткой или копипастой чужого
  конфига. Любое другое значение = `ConfigError` на старте, не тихий фолбэк.
- Каждая загрузка конфига пишет **WARNING в лог**: у решения есть владелец, и
  видно, что режим включён явно клиентом, а не приехал нашим дефолтом.
- `/config` показывает эту строку с ⚠️, а не как рядовую настройку.
- **Раскрытие ИИ в переписке регулируется** (EU AI Act, California B.O.T. Act и
  аналоги). Юрисдикцию и риск оценивает владелец аккаунта — это его решение и
  его ответственность. Проговорить с клиентом под запись, как и выделенность
  аккаунта на шаге 7.

Что **не** меняется: вопрос «ты бот?» по-прежнему **эскалируется владельцу** в
обоих режимах. Тумблер меняет ответ лиду, а не видимость для владельца.

## 7. Включить гейт воронки — командой (2 мин)

```
/funnel_gate            → показать текущее состояние
/funnel_gate on         → предупреждение + просьба подтвердить
/funnel_gate on confirm → ✅ ВКЛ
/funnel_gate off        → выключить (сразу, без подтверждения)
```

Команда сама пишет `settings.yaml`, перечитывает конфиг и переживает рестарт.
Комментарии в файле сохраняются. Правка руками больше не нужна.

**🚫 ПРАВИЛО (инцидент 2026-07-22): целевое состояние НИКОГДА не пишется в
живой конфиг заранее — в файле только ФАКТ.** Гардиан деплоит из рабочего
дерева: «запишу true, включим позже» означает, что любой рестарт/ребут поднимет
раннер с открытым гейтом БЕЗ команды владельца (плюс catch-up веером по
незнакомцам за сутки). Прецедент: `funnel_gate: true` вписали в
`volska/settings.yaml` как «цільовий стан» перед мержем — мину сняли до ребута.
Целевое состояние живёт в задаче/чеклисте; в конфиг оно попадает только
командой пульта в момент реального включения. Это касается любого ключа
конфига, не только гейта.

## 8. Проверка инверсии гейта (2 мин)

Приоритет: `denylist` > `allowlist` > `contact` > `stranger`.

| Кто | `is_contact` | Решение |
|---|---|---|
| Незнакомец (лид) | False | `answer` — Аня ведёт диалог |
| Контакт владельца | True | `notify_owner` — **Аня молчит, владельцу уведомление** |
| id из allowlist | True | `answer` (override) |
| id из denylist | — | `block_denylist` |

**Живая проверка обязательна, 2 аккаунта:** незнакомец получает ответ; контакт
не получает, а владельцу падает уведомление. Если п.2 не сработал — проверить,
что аккаунт реально `contact` в Telegram, а не «просто переписывались».

## 9. Привязка пульта клиенту (1 мин)

Отдать клиенту `t.me/<bot_username>?start=acme-onboard-01` — один тап,
вводить ничего не надо.

| Действие | Результат |
|---|---|
| Чужой `/start` без кода | отказ |
| Чужой `/start wrong-code` | отказ |
| `/start <верный код>` | ✅ привязан |
| Чужой повторно тем же кодом | **отказ — привязка не перебивается** |

Привязка живёт в SQLite, переживает рестарт. Разорвать — только `/unbind`
от владельца. Финально: клиент жмёт кнопку на карточке эскалации.

**~26 минут, из них 10 — ожидание кода в Telegram.** Разработчик не нужен
ни на одном шаге.

### Что осталось ручным — и почему это нормально

- **Строка в `active.yaml`** — это и есть конфиг состава; одна строка, не файл с нуля.
- **Токен в `.env`** — секрет-канал (DEV-2): значения секретов вводит владелец
  интерактивно, автоматизации тут быть не должно.
- **Текст `persona.md` / `playbook.md`** — авторская работа под клиента, а не
  заполнение формы. Шаблон даёт рабочую заготовку; тон и стоп-сигналы пишет человек.
  `knowledge.md` при этом заливается командой `/knowledge`.
- **`safe_payment_reply: "ЗАПОЛНИТЬ"`** в шаблоне — заполнить под способы оплаты клиента.

### Первая строка `persona.md`

Она уходит в ответ на «ты бот?». Разметка теперь срезается (`# Аня` → `Аня`),
front-matter пропускается, проза предпочитается заголовку. Шаблон генератора
начинается с прозы намеренно. Но **осмысленная** первая строка — всё ещё на
авторе: она задаёт тон самого доверительного сообщения продукта.

## Что менялось в проде (проверить до мержа)

1. **Пути рантайма.** Раньше `.secrets/chatter_telethon.{session,db}` для всех.
   Теперь `.secrets/<первичный-slug>.{session,db}`. Живой деплой (`demo,demo2`)
   получает **одноразовую автомиграцию** при старте: файлы переименовываются в
   `demo.session` / `demo.db`, в лог падает `онбординг-№4: перенёс …`.
   Проверено на копии боевой раскладки — сессия сохраняется, разлогина нет.
   Миграция срабатывает только в путь legacy-владельца (`demo`), чтобы новый
   клиент не подхватил чужую сессию.
2. **Состав клиентов.** `chatter/clients/active.yaml` = `demo, demo2` — ровно
   то, что крутится сейчас. Тест сверяет файл с реальностью.
3. **Контракт конфига ослаблен.** `timings`/`limits`/`work_hours` стали
   необязательными. Существующие `settings.yaml` не трогали — они валидны.
4. **Откат.** `git revert` арки. Если откатывать ПОСЛЕ миграции путей —
   переименовать `.secrets/demo.session` → `.secrets/chatter_telethon.session`
   обратно, иначе старый код не найдёт сессию.

## Отладка

| Симптом | Смотреть |
|---|---|
| Аня молчит | `/config` (гейт? allowlist?), затем лог раннера |
| `/reload` ругается | причина названа в ответе; Аня работает на **прежнем** конфиге |
| Конфиг сломан после правки | `/rollback` — вернуть предыдущую версию |
| Пульт не отвечает | владелец нажал `/start`? привязка в `control_owner_chat_id` |
| Ответ начинается со странного | первая строка `persona.md` |
